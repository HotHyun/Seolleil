# 트립 선택·예약 지원 1차 기획

구현 상태: 1·2차 Scope 구현 완료. 예약 상태는 체크리스트를 단일 기준으로 사용하며 실시간 재고·예약 대행은 제외한다.

## 2차 Scope

- 트립 사이드바의 `스키 일정 & 렌탈`, `숙박`, `교통` 탭에서 각 후보와 조건을 집중해서 비교한다.
- 데스크톱은 지도+목록 2열, 모바일은 지도와 선택 패널이 이어지는 단일 흐름을 사용한다.
- 렌탈 목록은 픽업, 의류, 리프트권, 25/26 가격 확인 조건으로 좁힐 수 있고 숙박은 공식 시설 후보만 제공한다.
- 렌탈 목록은 거리순·가격순·검증순 정렬을 제공하며 이미 저장한 업체는 정렬 기준과 관계없이 가장 먼저 보여준다.
- 지도 마커와 목록 선택 상태를 동기화한다. Kakao Map 키·좌표가 없어도 목록 비교와 트립 저장은 유지한다.
- 지도 마커를 선택하면 해당 렌탈 카드가 펼쳐지고 스크롤 목록 안의 카드로 부드럽게 이동한다. 모션 축소 설정에서는 즉시 이동한다.
- 렌탈과 숙박 마커는 색상과 문자(R/H)를 함께 사용해 구분하며, 선택 마커는 크기와 외곽선으로 한 번 더 강조한다.
- 가격 확인 렌탈샵은 상품 선택 후 예상 비용을 갱신한다. 가격 미확인 업체는 업체만 저장하고 실제 비용 직접 입력을 안내한다.
- 렌탈샵 카드에서 장비·의류와 할인 리프트권을 별도 선택으로 저장한다. 할인권은 같은 시간대 공식 정상가가 확인된 경우에만 1인 절감액·절감률·전체 인원 절감액을 표시한다.
- 여행 기간 안에서 실제 스키 날짜를 고르고 날짜마다 이용 시간, 렌탈샵, 장비, 의류, 추가 장비와 리프트권을 독립적으로 저장한다. 같은 조건 적용은 선택 사항이며 날짜별 시간에 맞는 상품으로 연결한다.
- 장비와 의류는 개별 선택을 기본으로 제공하고 결합 패키지가 실제로 저렴할 때 절감액을 표시한다.
- 렌탈 선택 전 상태는 `장비를 선택하세요`처럼 선택이 필요함을 표시하며 상품 부재로 표현하지 않는다. 선택 날짜가 정적 가격 유효기간 밖이면 `새 시즌 가격 미공개`로 구분하고 지난 시즌 참고 범위와 최신 가격 원문만 제공하며, 과거 가격을 해당 날짜의 확정 선택이나 예상 비용으로 저장하지 않는다.
- 공식 리조트 시간권을 다시 저장하면 할인권 선택만 해제하며 장비·의류 렌탈 선택은 유지한다.
- 숙박은 체크인하는 밤 단위로 숙소명·공식 URL·1박 비용을 저장한다. 같은 숙소와 금액은 모든 숙박 밤에 한 번에 적용한 뒤 달라지는 밤만 수정할 수 있다. 당일치기에는 숙박 입력 대신 숙박 없음 상태를 명시한다.
- 교통은 스키 날짜마다 반복하지 않고 도착일의 `가는 길`과 출발일의 `돌아오는 길` 두 구간으로 저장한다. 이동수단과 셔틀 노선·정류장은 구간별로 독립 선택한다. 가는 편은 지역 탑승지·출발 시각, 오는 편은 리조트 승차 위치·출발 시각과 귀가 하차지를 별도 문맥으로 보여준다.
- 선택은 관련 체크리스트를 `planned`로 전환할 수 있지만 `reserved`·`paid`는 사용자가 체크리스트에서 직접 확정한다.
- 음식점, 외부 숙박 대규모 수집, 외부 평점, 실시간 가격·재고와 예약·결제 대행은 제외한다.

## 문제와 방향

체크리스트는 준비 누락을 막는 도구이고, 개요는 현재 선택 결과를 빠르게 확인하는 대시보드여야 한다. 렌탈샵·리프트권·교통·숙박처럼 사용자가 비교하고 결정해야 하는 과정까지 체크리스트 안에 넣으면 화면의 역할이 섞인다. 따라서 별도의 `선택·예약` 작업 공간에서 비교와 선택을 돕고, 체크리스트는 관련 항목에서 해당 화면으로 이동시키는 구조를 사용한다.

이 방향은 추천에서 트립 생성, 실제 예약 준비, 비용 확정, 정산까지 하나의 트립 상태로 연결하므로 제품의 핵심 가치와 맞는다. 다만 실시간 재고나 예약 대행 없이 정적 시즌 데이터와 공식 원문 링크를 기반으로 신뢰 범위를 명확히 한다.

## 정보 구조

- `개요`: 리프트권, 렌탈, 교통, 숙박의 선택·예약 상태와 예상/확정 비용을 한눈에 보여주는 대시보드.
- `스키 일정 & 렌탈`: 여행 기간 중 스키 날짜와 시간, 렌탈 후보, 날짜별 장비·의류·추가 장비, 리프트권을 함께 처리하는 작업 공간.
- `숙박`: 숙박 밤 탭, 공식 숙소 위치 비교, 밤별 숙박 정보와 1박 비용 기록을 처리하는 작업 공간.
- `교통`: 가는 길/돌아오는 길 탭, 구간별 이동수단, 셔틀 노선과 탑승지 선택을 처리하는 작업 공간.
- `체크리스트`: 가져갈 것과 예약/결제/준비 상태를 관리하고, 결정이 필요한 항목에는 해당 선택 화면 CTA를 제공.
- `비용·정산`: 선택 결과를 읽기 전용 요약으로 받고 사용자가 실제 금액을 수정하거나 추가 비용을 넣어 1/N을 계산. 선택 변경은 해당 선택·예약 탭으로 이동해 처리한다.

## 1차 Scope

### 개요 대시보드

- 리프트권 시간권과 구매 상태.
- 선택한 렌탈샵, 렌탈 품목, 예상/확정 금액과 예약 상태.
- 교통수단, 셔틀이면 노선/탑승 지점과 예약 상태.
- 숙소명, 외부 링크, 사용자가 입력한 실제 금액과 예약 상태.
- 미결정 항목은 경고 문장 대신 명확한 `둘러보기` CTA를 표시한다.

### 선택·예약 작업 공간

- 긴 단일 화면 대신 사이드바에서 `렌탈샵 & 리프트`, `숙박`, `교통` 세 탭으로 분리한다. 모바일에서는 같은 항목을 가로 스크롤 가능한 작업 탭으로 제공한다.
- 각 탭에는 해당 결정에 필요한 콘텐츠만 렌더링하며 URL의 `view` 값으로 현재 탭을 유지한다.
- 렌탈샵과 리프트권은 할인 판매와 패키지 가능성을 함께 판단할 수 있도록 같은 탭에 둔다.
- 렌탈샵을 1차 핵심 카테고리로 구현한다. 이름, 스키장과의 위치/거리, 제공 품목, 시즌 가격, 추천 이유, 출처·공식 링크를 비교하고 옵션을 선택한다.
- 지도는 후보 위치 관계를 보조하며 카드 비교가 기본 인터페이스다. 지도 API가 없거나 좌표가 부족해도 목록 비교와 선택이 가능해야 한다.
- 셔틀은 운영사, 출발 지점, 대상 스키장, 시즌 기준 정보, 공식 예약 링크를 제공하고 사용자가 이용 노선을 기록한다.
- 공개된 경우 편도·왕복·시즌권 요금, 무료 여부, 운행 기간·요일, 예약 마감, 최소 출발 인원과 예약 조건을 구조화해 제공한다. 공개되지 않은 조건은 임의로 추정하지 않고 예약 원문 확인 대상으로 남긴다.
- 하이원 25/26 제휴 스키버스는 운영사별 정적 노선 데이터로 제공한다. 사용자는 리조트 상세와 트립 교통 결정 화면에서 권역 또는 도시·역 이름으로 검색하고, 정류장 순서·출발 시각·운행 조건·예약 원문을 확인한다.
- 귀가편은 `returnService`로 리조트 출발 위치·시각·하차 순서를 구조화한다. 운영사가 역순 운행을 명시한 경우에만 역순으로 표시하고, 시간이나 순서를 공개하지 않은 경우에는 예약 원문 재확인 상태를 유지한다. 지역별 요금이 다르면 정류장 단위 편도·왕복 요금을 사용한다.
- 모든 리조트 상세는 셔틀 조사 상태를 숨기지 않는다. 공개 시간까지 확인된 노선은 `확정 시간표`, 노선만 확인되었거나 다음 시즌 확인이 필요한 노선은 `시간 재확인`, 일반 고객용 25/26 제휴편을 확인하지 못한 리조트는 `운행 없음`으로 표시한다.
- `운행 없음`은 시외·고속버스와 행사·강습 전용 차량을 제외한 결과임을 안내하고, 리조트 공식 교통 페이지로 연결한다. 트립의 교통 결정 화면에서도 같은 안내를 제공한다.
- 종료 시즌 정보에는 종료 상태와 다음 시즌 재확인 안내를 항상 표시한다. 당시 운행만 확인되고 시간표를 복원하지 못한 노선은 `route_only_25_26`으로 구분하여 정확한 시각처럼 노출하지 않는다.
- 숙박은 가격 추천을 하지 않는다. 스키장 주변 숙박 탐색 링크를 제공하고 사용자가 숙소명·예약 URL·실제 금액을 기록한다.
- 선택 상태와 예약 상태를 분리한다. 외부 링크 방문만으로 예약 완료를 추정하지 않는다.

### 체크리스트 연결

- `렌탈샵 선택`, `장비/의류 렌탈 예약`, `셔틀/버스 예약`, `숙박 예약`, `리프트권 구매` 항목에 문맥별 CTA를 붙인다.
- CTA는 체크리스트 안에 비교 UI를 펼치지 않고 `선택·예약`의 해당 카테고리로 이동한다.
- 선택 완료 시 관련 항목을 `planned`로 제안하거나 전환하되 `reserved`, `paid`는 사용자가 직접 확정한다.
- 체크리스트는 미완료 항목만 좁혀 볼 수 있고, 상단 주의 항목에서 해당 카테고리와 항목으로 바로 이동한다. 사용자 추가 항목 삭제는 확인 후 실행한다.
- 선택한 왕복 구간별 이동수단과 셔틀 노선·탑승지·예약 링크는 트립 개요에 요약한다. 같은 셔틀 노선의 구조화된 왕복 요금이 있으면 한 번만 적용하고, 서로 다른 구간은 편도 요금 또는 왕복 요금의 추정 편도분을 합산한다. 실제 지출은 예산 화면에서 덮어쓸 수 있다.

### 트립 기본 정보 편집

- 관리 메뉴의 큰 `트립 수정` 화면을 제거한다.
- 트립명 옆 연필 버튼에서 이름만 dialog로 수정한다.
- 날짜·인원 등 기본 조건은 별도 `여행 기본 설정`으로 유지한다.
- 비용 관련 저장 버튼은 결과를 과장하는 `비용 다시 재계산하기` 대신 `저장하기`로 표시한다.

## 데이터 운영과 신뢰

- 렌탈샵·셔틀 데이터는 시즌별 정적 운영 데이터로 관리하고 출처 URL과 적용 시즌을 필수로 둔다. 셔틀은 원본 노선, 리조트별 커버리지, 운영사·정류장·시즌 색인을 분리하되 색인은 원본 노선에서 생성해 중복 입력을 피한다.
- 가격에는 예상/사용자 확정 여부를 구분한다.
- 링크 상태 검사는 접근 가능 여부만 보조하며 가격·재고 최신성을 보증하지 않는다.
- 숙박 가격, 실시간 재고, 앱 내 결제·예약, 음식점, 자동 크롤링은 1차 Scope에서 제외한다.

## 권장 구현 순서

1. 선택 결과와 예약 상태 데이터 모델, 개요 대시보드.
2. 렌탈샵 비교·선택과 체크리스트 CTA 연결.
3. 셔틀 정보·선택과 숙박 직접 기록 흐름.
4. 트립 이름 인라인 편집과 기본 설정 분리.
5. 비용·정산 연결 및 모바일/공유 권한 회귀 테스트.
