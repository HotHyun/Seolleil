# 트립 선택·예약 지원 1차 기획

## 문제와 방향

체크리스트는 준비 누락을 막는 도구이고, 개요는 현재 선택 결과를 빠르게 확인하는 대시보드여야 한다. 렌탈샵·리프트권·교통·숙박처럼 사용자가 비교하고 결정해야 하는 과정까지 체크리스트 안에 넣으면 화면의 역할이 섞인다. 따라서 별도의 `선택·예약` 작업 공간에서 비교와 선택을 돕고, 체크리스트는 관련 항목에서 해당 화면으로 이동시키는 구조를 사용한다.

이 방향은 추천에서 트립 생성, 실제 예약 준비, 비용 확정, 정산까지 하나의 트립 상태로 연결하므로 제품의 핵심 가치와 맞는다. 다만 실시간 재고나 예약 대행 없이 정적 시즌 데이터와 공식 원문 링크를 기반으로 신뢰 범위를 명확히 한다.

## 정보 구조

- `개요`: 리프트권, 렌탈, 교통, 숙박의 선택·예약 상태와 예상/확정 비용을 한눈에 보여주는 대시보드.
- `선택·예약`: 카테고리별 후보 비교, 추천 이유, 출처, 외부 예약 링크, 최종 선택을 처리하는 작업 공간.
- `체크리스트`: 가져갈 것과 예약/결제/준비 상태를 관리하고, 결정이 필요한 항목에는 해당 선택 화면 CTA를 제공.
- `비용·정산`: 선택 결과의 가격을 기본값으로 받고 사용자가 실제 금액을 수정하거나 추가 비용을 넣어 1/N을 계산.

## 1차 Scope

### 개요 대시보드

- 리프트권 시간권과 구매 상태.
- 선택한 렌탈샵, 렌탈 품목, 예상/확정 금액과 예약 상태.
- 교통수단, 셔틀이면 노선/탑승 지점과 예약 상태.
- 숙소명, 외부 링크, 사용자가 입력한 실제 금액과 예약 상태.
- 미결정 항목은 경고 문장 대신 명확한 `둘러보기` CTA를 표시한다.

### 선택·예약 작업 공간

- 렌탈샵을 1차 핵심 카테고리로 구현한다. 이름, 스키장과의 위치/거리, 제공 품목, 시즌 가격, 추천 이유, 출처·공식 링크를 비교하고 옵션을 선택한다.
- 지도는 후보 위치 관계를 보조하며 카드 비교가 기본 인터페이스다. 지도 API가 없거나 좌표가 부족해도 목록 비교와 선택이 가능해야 한다.
- 셔틀은 운영사, 출발 지점, 대상 스키장, 시즌 기준 정보, 공식 예약 링크를 제공하고 사용자가 이용 노선을 기록한다.
- 숙박은 가격 추천을 하지 않는다. 스키장 주변 숙박 탐색 링크를 제공하고 사용자가 숙소명·예약 URL·실제 금액을 기록한다.
- 선택 상태와 예약 상태를 분리한다. 외부 링크 방문만으로 예약 완료를 추정하지 않는다.

### 체크리스트 연결

- `렌탈샵 선택`, `장비/의류 렌탈 예약`, `셔틀/버스 예약`, `숙박 예약`, `리프트권 구매` 항목에 문맥별 CTA를 붙인다.
- CTA는 체크리스트 안에 비교 UI를 펼치지 않고 `선택·예약`의 해당 카테고리로 이동한다.
- 선택 완료 시 관련 항목을 `planned`로 제안하거나 전환하되 `reserved`, `paid`는 사용자가 직접 확정한다.

### 트립 기본 정보 편집

- 관리 메뉴의 큰 `트립 수정` 화면을 제거한다.
- 트립명 옆 연필 버튼에서 이름만 dialog로 수정한다.
- 메모가 없으면 `메모 추가`, 있으면 인라인 편집 동작을 제공한다.
- 날짜·인원 등 기본 조건은 별도 `여행 기본 설정`으로 유지한다.
- 비용 관련 저장 버튼은 결과를 과장하는 `비용 다시 재계산하기` 대신 `저장하기`로 표시한다.

## 데이터 운영과 신뢰

- 렌탈샵·셔틀 데이터는 시즌별 정적 운영 데이터로 관리하고 출처 URL과 적용 시즌을 필수로 둔다.
- 가격에는 예상/사용자 확정 여부를 구분한다.
- 링크 상태 검사는 접근 가능 여부만 보조하며 가격·재고 최신성을 보증하지 않는다.
- 숙박 가격, 실시간 재고, 앱 내 결제·예약, 음식점, 자동 크롤링은 1차 Scope에서 제외한다.

## 권장 구현 순서

1. 선택 결과와 예약 상태 데이터 모델, 개요 대시보드.
2. 렌탈샵 비교·선택과 체크리스트 CTA 연결.
3. 셔틀 정보·선택과 숙박 직접 기록 흐름.
4. 트립 이름·메모 인라인 편집과 기본 설정 분리.
5. 비용·정산 연결 및 모바일/공유 권한 회귀 테스트.
