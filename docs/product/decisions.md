# 확정된 의사결정

## 제품 방향

- 제품명: Korean Ski.
- 제품 형태: 모바일 우선 웹 플랫폼.
- MVP 핵심 가치: 사용자가 국내 스키장을 고르고, 방문 전 필요한 예약/결제/준비 항목을 빠뜨리지 않도록 돕는다.
- 초기 스키장 범위: 일부 주요 스키장이 아니라 국내 운영 스키장 전체.
- 로그인: MVP에 선택적 로그인을 포함한다.
- 인증 제공자: Google OAuth를 1차로 지원한다.
- Kakao OAuth와 이메일 매직링크는 추후 확장으로 둔다.
- 비로그인 트립 생성은 유지한다.
- 로그인 사용자는 "내 트립" 목록에서 자신이 만든 트립을 다시 열 수 있다.
- 비로그인으로 만든 트립은 edit link로 접근한 뒤 로그인 계정에 연결할 수 있다.
- 트립 저장: 서버 DB에 저장.
- 트립 접근 방식:
  - 로그인 사용자의 내 트립 목록.
  - 소유자용 편집 링크.
  - 공유용 읽기 전용 링크.
- 트립 보관 기간: 시즌 단위 보관.
- 공유 링크 노출 정보:
  - 일정.
  - 체크리스트.
  - 예약/준비 상태.
  - 민감 정보나 개인 메모는 노출하지 않음.
- 예약/결제: MVP에서는 자체 처리하지 않고 외부 링크로 이동.
- 설질/슬로프/운영 현황: 서비스에서 직접 크롤링하지 않고 공식 페이지 링크를 제공.

## 가격 정책

- 가격은 사용자가 선택한 방문 날짜 기준으로 달라져야 한다.
- 가격 데이터는 시즌별 static 코드 데이터로 관리한다.
- MVP에는 가격 관리자 화면을 만들지 않는다.
- MVP에는 프로덕션 크롤러를 붙이지 않는다.
- AI는 공식 가격 페이지 조사 보조 도구로 사용한다.
- 개발자가 가격을 직접 검증한 뒤 코드에 반영하고 재배포한다.
- 모든 가격 규칙에는 출처 URL, 마지막 확인일, 수동 검증 여부를 남긴다.

## 비용 계산 항목

MVP 예상 비용에는 아래 항목을 포함한다.

- 리프트권.
- 장비 렌탈.
- 의류 렌탈.
- 숙박비: 사용자가 직접 입력.
- 교통비.

교통비 정책:

- 자차: 거리 기반 예상 유류비 + 통행료 + 주차비.
- 셔틀/버스: 확보 가능한 노선 가격 static 데이터 사용.
- 대중교통: MVP 비용 계산에서 제외.

## 사용자 입력 정책

- 숙박비는 사용자가 직접 입력한다.
- 리프트권 시간권은 사용자가 직접 선택한다.
- 추천 기준은 사용자가 1순위~3순위 선호를 입력할 수 있게 한다.

## 배포 환경 가정

초기 배포 환경은 OCI Free Tier Ampere 인스턴스를 사용한다.

- 4 OCPU.
- 24 GB RAM.
- 200 GB Disk.
- ARM 아키텍처.

## 기술 스택

- 웹 프레임워크: Next.js.
- 데이터베이스: PostgreSQL.
- ORM: Prisma.
- 배포 방식: Docker Compose.
- 호스팅/운영: Coolify에서 Docker Compose 기반으로 운영.
- 프론트 방향: 모바일 웹 중심으로 설계하되 데스크톱도 대응한다.

## 성과 측정/분석

- 웹 분석 도구: Umami self-host.
- Umami 운영 방식: Coolify에서 별도 서비스로 운영.
- 앱에는 Umami tracking script를 삽입한다.
- 제품 핵심 이벤트는 PostgreSQL의 자체 이벤트 테이블에도 저장한다.
- MVP 단계에서는 별도 관리자 대시보드를 만들지 않는다.
- MVP 단계의 DB 이벤트 확인은 PgAdmin을 사용한다.
- Umami 용 PostgreSQL은 앱 DB와 분리된 별도 DB로 운영하는 것을 기본으로 한다.
- 이벤트에는 개인정보, editToken/shareToken 원문을 저장하지 않는다.

## UI/스타일링

- 스타일링: Tailwind CSS.
- UI 컴포넌트: shadcn/ui.
- 아이콘: lucide-react.
- 폼 관리: react-hook-form + zod.
- 기본 테마: 라이트 테마.
- 디자인 톤: 실용적인 트립 플래너를 중심으로 여행 예약 서비스 감각을 일부 결합한다.
- 컬러 방향: 화이트/차콜 기반에 라임 액센트.
- 레이아웃: 모바일 1열 중심, 데스크톱 2열 확장.
- 지도: MVP에서는 지도 API 연동 없이 네이버 지도/카카오맵 외부 링크 제공.
- 데이터 시각화: 차트는 제외하고 준비 진행률, 총 예상 비용, 예약 필요 항목 요약을 중심으로 표시한다.

## 스키장 데이터셋

- 데이터 범위: 운영/휴장/폐장 상태를 포함한 국내 스키장 전체.
- 기본 노출: 운영 중/시즌 오픈 예정 스키장을 기본 노출하고, 휴장/폐장은 필터나 상태 표시로 확인 가능하게 한다.
- 추천 대상: `operating` 상태의 스키장만 추천한다.
- 비시즌에는 `season_pending` 스키장을 "시즌 오픈 예정" 섹션에 표시할 수 있다.
- 스키장 데이터는 DB가 아니라 static 코드 데이터로 관리한다.
- 지도 링크는 네이버 지도와 카카오맵을 제공한다.
- 가격 데이터가 없는 스키장도 추천 가능하되 "가격 확인 필요"로 표시한다.
- 예약 링크는 공식 사이트, 공식 예약처, 네이버 예약, 여행사/패키지 링크까지 포함할 수 있다.
- 렌탈 정보는 리조트 공식 렌탈뿐 아니라 외부 렌탈샵도 수동 등록한다.
- 강습 정보는 1차 MVP에서 제외한다.
- 데이터 검증 방식은 AI 조사 → 개발자 검증 → static 데이터 반영 흐름을 사용한다.

## 가격/렌탈샵 정책

- 렌탈 가격은 리조트 공식 렌탈과 외부 렌탈샵을 모두 포함한다.
- 렌탈 가격은 장비, 의류, 패키지별로 비교할 수 있게 한다.
- 렌탈 가격 단위는 성인/소인, 장비 종류, 패키지를 구분한다.
- 장비 종류는 MVP에서 스키/보드만 구분한다.
- 의류 렌탈은 성인/소인 + 세트 기준으로 관리한다.
- 보호장비, 헬멧, 고글 가격은 필수 비용에 넣지 않고 옵션으로 표시한다.
- 가격 표시는 검증된 대표 가격과 최저~최고 범위를 함께 보여준다.
- 총 예상 비용은 선택 전에는 범위로 표시하고, 사용자가 렌탈샵/옵션을 선택하면 선택 옵션 기준으로 계산한다.
- 사용자는 렌탈샵과 옵션을 선택할 수 있다.
- 외부 렌탈샵 추천은 가격, 거리, 의류/장비 제공 여부, 수동 추천 태그를 함께 반영한다.
- 가격 출처는 공식 웹사이트, 네이버 예약, 스마트스토어, 여행사, 전화 문의를 모두 허용하되 출처 타입을 표시한다.
- 가격 유효 기간은 날짜 범위, 요일, 성수기/비수기 구분을 포함한다.
- 가격 신뢰도는 `confirmed`, `estimated`, `phone_confirmed`, `unavailable`을 사용한다.
- 할인/쿠폰 전체 추적은 제외하고 대표 패키지만 등록한다.
- 숙박 가격은 사용자가 직접 입력한다.
- 가격 변경 감지는 AI 조사 보조를 활용하되, 개발자가 검증 후 수동 반영한다.

## 트립 생성 플로우

- 트립은 사용자가 스키장 선택 후 "트립 만들기"를 클릭하는 시점에 DB에 저장한다.
- 조건 입력은 3단계 폼으로 구성한다.
- 추천 결과에서는 추천 카드를 선택한 뒤 옵션 확인 화면을 거쳐 트립을 생성한다.
- 렌탈샵 선택은 트립 생성 전 선택 가능하게 하되 건너뛸 수 있다.
- 숙박비는 조건 입력 단계에서 입력할 수 있고, 트립 상세에서 나중에 수정할 수 있다.
- 리프트권 시간권은 조건 입력 단계에서 선택한다.
- 추천 결과 가격은 항목별 요약과 총액 범위로 보여준다.
- 트립 생성 시 모든 기본 체크리스트 항목을 생성하고, 조건에 따라 필요 없는 항목은 `not_needed`로 표시한다.
- 트립 생성 후 날짜, 인원, 교통, 렌탈, 숙박비, 스키장 등 모든 주요 입력값을 수정할 수 있다.
- 트립 생성 완료 후에는 바로 트립 상세로 이동하고, 상단에 공유/편집 링크 안내 배너를 보여준다.
- 로그인하지 않은 사용자는 트립 상세에서 로그인 후 트립을 계정에 저장할 수 있다.
- 로그인한 사용자는 내 트립 목록에서 트립을 다시 열 수 있다.

## 체크리스트/상태값 정책

- 트립 생성 시 모든 기본 체크리스트 항목을 생성한다.
- 조건상 필요 없는 항목은 삭제하지 않고 `not_needed` 상태로 표시한다.
- 체크리스트 카테고리는 예약/구매, 렌탈, 교통, 숙박, 운영 확인, 준비물, 안전/기타로 나눈다.
- 상태값은 `not_needed`, `needs_check`, `planned`, `reserved`, `paid`, `prepared`를 사용한다.
- 모바일 상태 변경 UI는 바텀시트, 데스크톱은 드롭다운을 사용한다.
- 사용자는 직접 체크리스트 항목을 추가할 수 있다.
- 기본 항목은 삭제하지 않고 `not_needed`로 처리한다.
- 사용자 추가 항목은 삭제할 수 있다.
- 항목별 메모를 지원한다.
- 진행률은 `not_needed` 항목을 제외하고 계산한다.
- 완료 기준은 카테고리별로 다르게 적용한다.
- 기본 항목에는 자동 dueDate를 제공하고 사용자가 직접 수정할 수 있다.
- 공유 링크에서는 개인 메모를 숨기고 상태만 표시한다.
- 정렬은 카테고리별 고정 정렬을 사용한다.

## 추천 점수 계산

- 추천 대상은 `operating` 상태의 스키장으로 제한한다.
- 추천은 하드 필터 + 가중치 점수 + 설명 가능한 추천 이유로 구성한다.
- 하드 필터는 필수 조건에만 적용한다.
- 사용자 우선순위 가중치는 1순위 3점, 2순위 2점, 3순위 1점으로 계산한다.
- 기본 점수 카테고리는 접근성, 초보 친화, 가격, 야간 가능, 교통 접근성, 가족 친화, 리조트 규모, 렌탈 편의성이다.
- 가격 점수는 절대 가격과 사용자 예산 적합도를 함께 본다.
- 접근성 점수는 사용자의 출발지 기준 예상 거리/시간을 사용한다.
- MVP 출발지는 자유 입력이 아니라 주요 지역 선택 방식으로 시작한다.
- 추천 결과에는 점수표가 아니라 추천 이유 2~3개를 보여준다.
- 동점은 사용자 1순위 항목 우선, 그다음 접근성, 가격 순으로 처리한다.
- 가격 미확인 항목은 추천 제외가 아니라 약한 감점으로 처리한다.
- 기본 추천 결과는 3개이며 전체 보기 옵션을 제공한다.
- 내부 점수는 사용자에게 직접 노출하지 않는다.
- 사용자가 선택한 추천 결과 스냅샷만 저장한다.

## 공유 링크/보안 정책

- 편집 링크 URL: `/trips/{editToken}`.
- 공유 링크 URL: `/share/{shareToken}`.
- 로그인 사용자 트립 목록 URL: `/my-trips`.
- 토큰 형식: nanoid 21자.
- 토큰 저장 방식: 원문 토큰을 저장하지 않고 해시만 DB에 저장한다.
- 권한:
  - 로그인 사용자는 본인 계정에 연결된 트립을 수정 가능.
  - editToken은 트립 수정 가능.
  - shareToken은 읽기 전용.
- 시즌 종료 후 정책:
  - 읽기는 가능.
  - 수정은 비활성화.
- 삭제 기능: 편집 링크에서 삭제 가능.
- 공유 링크 체크리스트 노출: 전체 상태를 노출.
- 공유 링크 검색 노출: `noindex`로 검색엔진 색인을 차단.
- 편집 링크 UX:
  - "이 링크를 가진 사람은 수정할 수 있음" 안내를 표시.
  - 공유 동작은 기본적으로 읽기 전용 공유 링크만 복사하게 한다.
