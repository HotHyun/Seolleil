# 마케팅 전략 · 비즈니스 모델 (BM)

작성일 2026-11-19. 현재 코드·문서 기준 진단이며, 수치 목표는 가정이다(실측 후 보정).

## 1. 현황 진단

**제품 완성도 (MVP 기능 완료, SEO까지 끝남)**
- 스키장 13곳 이상 디렉토리, 룰 기반 추천(관점별 3곳), 방문일 기준 가격 계산(출처·신뢰도 라벨).
- 트립 작업공간: 날짜별 렌탈·리프트·의류, 숙박(공식 + 주변 후보 48곳), 교통(셔틀 노선·정류장), 체크리스트, 비용 원장과 1/N 정산.
- 렌탈샵 약 140곳(검증 82 + 발굴 63), 지도 비교, 25/26 참고가 + 일부 26/27 확정가.
- 익명 트립 + 편집/공유/초대 링크, 로그인(Google/이메일), 내 트립, 약관·방침, Umami·서버 이벤트.
- 인프라 비용이 낮은 Cloudflare Workers + Firestore 구조.

**강점**: 흩어진 정보(리프트·렌탈·셔틀·숙박)를 "한 트립"으로 묶는 점, 가격 출처 투명성, 로그인 없이 시작 가능, 동행 공유.
**약점**: 정적 데이터라 갱신 부담과 신뢰 리스크, 실시간 재고·예약 불가, 수익원 0개(제휴 링크 구조 없음), 트래픽·유저 데이터 없음, 1인 운영.
**타이밍**: 26/27 시즌 개장 직전(11~12월). 지금이 첫 시즌 트래픽을 확보할 유일한 창이며, 놓치면 다음 수요 피크는 내년 가을이다.

## 2. 포지셔닝

> "스키장 고르고, 렌탈·셔틀·숙소 비용까지 한 번에 비교하고, 친구와 같이 준비하는 스키 트립 플래너"

- 경쟁은 스키장 공식 사이트(단일 리조트), 네이버 블로그/카페(비교 정보 파편), 렌탈샵 예약 채널(개별), 여행 OTA(스키 특화 없음).
- 차별점 3가지를 메시지로 고정: ① **총비용 비교**(리프트+렌탈+교통+숙박) ② **초보자 체크리스트** ③ **링크 하나로 동행 공유·1/N 정산**.
- 주의: "최저가/실시간"을 약속하지 않는다. "출처 있는 시즌 참고가"가 신뢰 자산이다.

|---|---|---|---|
| 1 | 수도권 20~30대 초보·입문(친구/커플) | 뭘 준비하고 얼마 드는지 | 네이버 검색, 인스타 릴스, 커뮤니티 |
| 2 | 당일치기 주말 이용자 | 가까움·야간·셔틀 | 검색, 오픈채팅 |

| 후순위 | 가족 | 숙박·강습 | 맘카페 (데이터 보강 후) |

## 4. 마케팅 전략

### 4-1. 퍼널 목표 (가정치, 첫 시즌)
유입 → 트립 시작 → 추천 확인 → 트립 생성 → 렌탈/교통 선택 저장 → 공유 → 재방문.
북극성 지표는 문서 기준 그대로 **"트립 생성 후 체크리스트/선택을 실제 업데이트한 비율"**. 보조: 공유 링크 생성률(바이럴 계수), 외부 예약 링크 클릭률(수익 직결).

### 4-2. 채널별 실행

1. **검색(최우선, 비용 0)** — 네이버 서치어드바이저·Search Console 등록과 sitemap 제출(문서상 "사람이 할 일"로 남아 있음, 즉시 실행). 롱테일 랜딩 확장:
   - `/resorts/[id]` 외에 "OO 리프트권 가격", "OO 렌탈샵 비교", "OO 셔틀버스 시간표", "수도권 스키장 당일치기", "스키 초보 준비물" 같은 가이드·비교 페이지를 정적 데이터에서 자동 생성.
   - 스키장 시즌 개장·할인 정보 갱신 시 lastmod 갱신, FAQ JSON-LD 추가.
2. **숏폼·SNS** — "스키장 5곳 총비용 비교", "초보 스키 준비물 체크리스트", "셔틀 vs 자차" 릴스·쇼츠. 앱 화면 녹화 + 가격표가 소재가 된다. 주 3회, 12~1월 집중.
3. **커뮤니티·카페** — 스키/보드 카페, 오픈채팅, 대학 동아리, 직장인 커뮤니티에 홍보가 아닌 "가격 정리표" 형태로 기여. 각 커뮤니티 규칙 확인 후 진행.
4. **제품 내 바이럴(가장 효율적)** — 공유 링크 미리보기(OG)를 "OO스키장 1/20 · 4명 · 1인 12.4만원" 형태로 개인화(개인정보·토큰 노출 금지, 공유 토큰 페이지는 noindex 유지). 공유 페이지 하단에 "나도 트립 만들기" CTA. 정산 요약을 카톡 공유 텍스트로 복사하는 버튼.
5. **파트너십** — 렌탈샵·셔틀 운영사·소규모 스키 숍에 "설레일 노출 대신 가격 최신화 제공" 제안. 데이터 신뢰도와 제휴 수익을 동시에 확보.
6. **유료 광고** — 시즌 초반엔 하지 않는다. 전환 데이터(트립 생성률, 링크 클릭률)가 쌓인 뒤 네이버 검색광고·인스타를 소액(주 5~10만 원)으로 테스트.

### 4-3. 시즌 캘린더
- **11월 말~12월 초(지금)**: 개장 맞춰 검색 등록, 베타 지인·커뮤니티 시딩, 피드백 수집.
- **12월~2월**: 성수기. 숏폼 집중, 연말·연초·설 연휴 특집(숙박·셔틀 마감이 빠른 시기, 알림 이메일).
- **3월**: 폐장 이후 시즌 회고, 시즌권·다음 시즌 대비 콘텐츠.
- **4~9월**: 데이터 구조 개선, 26/27 가격 확정 반영, 얼리버드 리프트·시즌권 시기(8~10월)에 콘텐츠 재가동.

### 4-4. 신뢰·운영 원칙
- "참고가" 라벨, 출처·확인일 유지, 오류 제보 버튼(렌탈샵 제보 링크 이미 있음)을 전면화해 **데이터 품질을 사용자와 함께 개선**하는 스토리로 활용.
- 후기·평점 같은 UGC는 아직 도입하지 않는다(MVP 제외 방침 유지).

## 5. 비즈니스 모델

원칙: **예약·결제 대행 없음, 사용자 무료, 수수료는 외부 예약처로 보내는 제휴 링크에서만**(현재 방침과 충돌하지 않는 범위). 광고성 노출은 "광고/제휴" 표기를 하고, 추천 순위는 제휴 여부와 무관하게 유지한다(신뢰가 핵심 자산).

### 5-1. 수익원 (우선순위)

| # | 모델 | 내용 | 난이도 | 시점 |
|---|---|---|---|---|
| 1 | **제휴 링크 수수료(CPS/CPA)** | 숙박(NOL, 여기어때 등), 리프트·렌탈 온라인 예약, 셔틀 예약 링크를 제휴 파라미터 링크로 교체. 이미 `external_link_click` 이벤트와 링크 구조가 있어 구현이 가장 쉽다. | 낮음 | 12월 |
| 2 | **렌탈샵·셔틀·소규모 숍 입점/추천 슬롯** | 정식 파트너로 가격 직접 갱신, "공식 파트너" 배지, 지도 상단 노출(광고 표기). 월 정액 또는 예약 클릭당 과금. | 중간 | 1~2월 협상, 다음 시즌 본격화 |
| 3 | **스폰서십/브랜드 제휴** | 스키 의류·장비·보험·여행자 보험 브랜드, 리조트 시즌 프로모션 배너(체크리스트 준비물 구매 링크 포함). | 중간 | 사용자 확보 후 |
| 4 | **프리미엄 구독(후보)** | 가격 변동·개장·셔틀 마감 알림, 무제한 트립, 단체 정산 리포트. 사용자 규모가 충분하지 않으면 보류. | 높음 | 다음 시즌 이후 검토 |
| 5 | **B2B 데이터/도구** | 동아리·회사 워크숍용 단체 트립 템플릿, 리조트에 수요 인사이트 리포트. | 높음 | 장기 |

### 5-2. 구현 필요 사항 (제품 측)
- 외부 링크에 제휴 URL 설정 가능한 데이터 필드와 `isSponsored/affiliate` 표기 컴포넌트.
- 약관·방침 갱신(제휴 링크 고지, 수집 항목 변경 시), 표시광고법상 대가 표기 문구.
- 클릭→(제휴사 리포트) 전환 확인용 이벤트(`external_link_click`에 `provider`, `category` 속성; 개인정보 제외).
- 알림 기능을 위한 이메일 수집 동의·발송 인프라는 구독 모델 검토 시점에 추가.

### 5-3. 단위 경제(참고용 가정)
- 서버 비용은 거의 0에 가깝고 주요 비용은 **데이터 갱신 인건비**와 마케팅이다.
- 제휴 수익은 `월 방문자 × 트립 생성률 × 링크 클릭률 × 예약 전환율 × 건당 수수료`로 계산된다. 실측 전에는 숫자를 확정하지 말고, 4주간 아래를 측정한 뒤 모델에 대입한다: 트립 생성률, 링크 클릭률, 카테고리별 클릭 비중(숙박/렌탈/셔틀).

## 6. 90일 실행 로드맵

**0~2주 (즉시)**
- 서치어드바이저·Search Console 등록, sitemap 제출, 카카오 공유 디버거 점검.
- Umami 퍼널 대시보드 구성(위 북극성·보조 지표), 이벤트 `provider/category` 속성 보강.
- 지인·커뮤니티 30~50명 베타 시딩, 피드백 폼.

**2~6주**
- 롱테일 가이드/비교 페이지 자동 생성, FAQ 스키마.
- 숏폼 콘텐츠 시리즈 시작(주 3회).
- 숙박·렌탈·셔틀 제휴 프로그램 신청, 제휴 링크 교체 + 고지 문구/약관 반영.
- 공유 페이지 CTA·OG 개선.

**6~12주**
- 지표 기반으로 유료 광고 소액 테스트.
- 렌탈샵·셔틀 운영사 5~10곳과 파트너 제안(가격 최신화 + 노출 패키지).
- 폐장 전 설문·회고로 다음 시즌 기능 우선순위 결정(알림, 단체 정산 등).

## 7. 성공 기준 (가정, 4주 후 재설정)
- 첫 시즌 말: 누적 트립 생성 수천 건 규모 목표, 트립 생성 후 선택 저장률 40%+, 공유 링크 생성률 20%+, 외부 예약 링크 클릭률 15%+.
- 제휴 수익 1건 이상 발생 확인(검증용) → 월 운영비를 넘는 시점을 손익분기 지표로 관리.

## 8. 리스크와 대응
- **데이터 부정확/구버전 가격**: 참고가 라벨, 확인일, 제보 채널, 파트너 직접 갱신. 가격 확정 전 광고성 문구 금지.
- **시즌성 매출 편중**: 4~9월에 콘텐츠·B2B(단체)·시즌권 얼리버드로 분산.
- **제휴로 인한 신뢰 훼손**: 추천 알고리즘과 제휴를 분리, 표기 철저.
- **1인 운영 한계**: 갱신 자동화(`scripts/` 링크·데이터 검증 확장), 파트너 입력 구조로 부담 이전.
- **법/정책**: 약관·방침 변경 고지 기준 준수, 표시광고 고지, 크롤링 금지 방침 유지.
