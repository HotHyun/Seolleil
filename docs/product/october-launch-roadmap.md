# 10월 런칭 로드맵

## 목표

2026년 10월에 설레일을 공개 가능한 MVP로 런칭한다.

단순히 기능이 있는 상태가 아니라, 사용자가 실제 겨울 스키 트립 준비에 참고할 수 있을 정도로 데이터, 추천, 가격 계산, 체크리스트, 공유 플로우의 신뢰도를 높인다.

## 런칭 형태

권장 런칭 단계:

1. 9월 내부 알파: 개발자 직접 검증, 지인 테스트 전 단계.
2. 10월 초 비공개 베타: 지인/소규모 사용자 대상.
3. 10월 중순 공개 베타: 실제 시즌 준비 수요 대상.
4. 10월 말 런칭 판단: 데이터 정확도와 핵심 지표를 보고 공개 범위 확대.

## 런칭 성공 기준

런칭 전 최소 기준:

- 국내 스키장 전체 데이터셋이 정리되어 있다.
- 운영/휴장/폐장 상태가 구분되어 있다.
- 추천 대상은 운영 또는 시즌 오픈 예정 스키장으로 제한된다.
- 가격 데이터에는 출처, 확인일, 적용 기간, 신뢰도가 있다.
- 사용자는 방문 날짜 기준으로 리프트권, 렌탈, 의류 렌탈, 교통비를 확인할 수 있다.
- 비로그인 트립 생성, 편집 링크, 지속적인 보기/편집 공유 링크가 정상 작동한다.
- 로그인 사용자는 내 트립 목록에서 만든 트립을 다시 열 수 있다.
- 비로그인으로 만든 트립은 로그인 후 계정에 연결할 수 있다.
- 모바일에서 조건 입력, 추천 비교, 체크리스트 수정이 불편하지 않다.
- `pnpm test:all`이 통과한다.
- 운영 DB 백업/복구 절차가 문서화되어 있다.
- Umami와 앱 DB 이벤트 수집이 정상 작동한다.

## 제품 품질 기준

### 데이터

- 스키장 데이터는 국내 전체를 기준으로 한다.
- 각 스키장에는 최소한 이름, 지역, 운영 상태, 공식 사이트, 운영현황 링크, 지도 링크가 있어야 한다.
- 가격이 없는 스키장은 표시 가능하지만 "가격 확인 필요" 상태를 명확히 보여준다.
- 예약 링크는 공식 사이트, 네이버 예약, 여행사/패키지 링크를 함께 허용한다.

### 가격

- 가격은 방문 날짜 기준으로 계산된다.
- 주중/주말, 성수기/비수기, 시간권 조건을 표현할 수 있어야 한다.
- 모든 가격 규칙에는 출처 URL, 확인일, 적용 기간, 신뢰도를 남긴다.
- 가격 신뢰도는 `confirmed`, `estimated`, `phone_confirmed`, `unavailable`을 사용한다.
- 사용자에게는 총액만 보여주지 않고 항목별 비용 근거를 함께 보여준다.

### 추천

- 추천 결과는 사용자가 납득할 수 있어야 한다.
- 추천 이유는 2~3개로 짧게 표시한다.
- 종합 추천 3곳 외에 가까움, 저렴함, 초보 친화, 야간 가능, 교통 편리 같은 관점별 추천을 제공한다.
- 내부 점수는 노출하지 않는다.
- 가격 미확인 항목은 추천 제외가 아니라 약한 감점으로 처리한다.

### 트립/체크리스트

- 트립 생성 후 사용자가 바로 다음 행동을 이해할 수 있어야 한다.
- 비로그인 사용자는 edit link를 저장해야 한다는 점을 명확히 이해할 수 있어야 한다.
- 로그인 사용자는 링크 없이도 내 트립 목록에서 트립을 복구할 수 있어야 한다.
- 체크리스트는 조건에 맞게 기본 항목을 생성하고, 필요 없는 항목은 `not_needed`로 둔다.
- 공유 링크에서는 일정, 체크리스트, 예약/준비 상태만 노출한다.
- 개인 메모나 편집 권한은 공유 링크에 노출하지 않는다.

### UI/UX

- 홈은 랜딩 페이지 역할과 트립 시작 화면 역할을 모두 해야 한다.
- 데스크톱 첫 화면이 비어 보이지 않아야 한다.
- 모바일에서 주요 CTA가 명확해야 한다.
- 조건 입력은 길어도 사용자가 현재 입력 맥락을 잃지 않아야 한다.
- 추천 결과는 카드만 나열하지 않고 비교가 가능해야 한다.
- 빈 상태, 에러 상태, 잘못된 토큰 상태가 방치되지 않아야 한다.
