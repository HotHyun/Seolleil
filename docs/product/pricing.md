# 가격 정책

## 시즌 전환 표시

- 2026/27 공식 가격 공개 전에는 검증 가능한 25/26 시즌 데이터를 참고 가격으로 유지한다.
- 추천 결과와 트립 비용 화면에는 `25/26 시즌 지난 시즌 참고 가격` 안내를 항상 표시한다.
- 사용자가 예약 가격으로 오해하지 않도록 공식 판매처 최신 가격 확인 문구를 함께 제공한다.
- 항목별로 `확인됨`, `추정`, `전화확인`, `확인필요` 신뢰도 배지를 표시한다.
- 마지막 확인일은 내부 데이터 품질 관리에는 유지하되 사용자 UI에는 노출하지 않는다.

## 기본 원칙

MVP 가격은 방문 날짜 기준으로 계산하되, 데이터는 static하게 관리한다.

Korean Ski는 MVP에서 프로덕션 크롤러나 가격 동기화 작업을 운영하지 않는다. 가격 데이터는 시즌별 코드 데이터로 관리한다.

현재 앱의 기준 시즌은 `2025-2026`이다. `2026-2027` 시즌 가격이 아직 확인되지 않은 항목은 25/26 시즌 자료를 출처가 표시된 참고 정보로만 유지한다.

2026/27 시즌 가격이 공개되면 기존 규칙을 덮어쓰지 않고 `2026-2027` 규칙을 나란히 추가한다. 리프트·렌탈·셔틀 전환이 완료된 뒤에만 `CURRENT_SEASON`을 갱신한다.

시즌 전환 상태는 리조트별·카테고리별로 다음 네 단계로 관리한다.

- `not_published`: 26/27 항목이 아직 등록되지 않음.
- `in_review`: 일부 항목이 등록됐거나 출처·유효 기간·신뢰도 확인이 남음.
- `confirmed`: 기존 항목에 대응하는 26/27 항목이 모두 확정됨.
- `unavailable`: 공식적으로 판매·운행하지 않음이 확인됨.

전환 우선순위는 P1 하이원·비발디·용평·휘닉스, P2 곤지암·지산·엘리시안·웰리힐리·알펜시아, P3 오크밸리·오투·무주·에덴밸리 순이다. `/admin/data-quality`에서 상태, 잔여 항목, 다음 조치를 확인한다.

공식 화면을 확인했지만 가격표가 아직 게시되지 않은 경우 `season-research.ts`에 `checked_unpublished`로 기록한다. 시즌패스나 운영 준비 일정처럼 다음 시즌을 확인할 수 있지만 트립 계산 상품과 직접 대응하지 않는 공지는 `preliminary`로 기록한다. 이 사전 공지는 관리자 전환 보드에서 보이지만 가격 규칙의 완료율에는 포함하지 않는다.

운영 흐름:

1. AI를 오프라인 조사 보조 도구로 사용해 공식 가격 페이지와 후보 가격 규칙을 찾는다.
2. 개발자가 공식 페이지를 직접 검증한다.
3. 검증한 내용을 시즌별 static 데이터에 반영한다.
4. 재배포한다.
5. 시즌 중 가격이 바뀌면 수동으로 패치 후 재배포한다.

동일 상품의 시즌별 규칙 구조가 달라질 때는 `replacementKey`를 명시해 전환 대응 관계를 유지한다. 구조가 같으면 리조트·상품·시간권·요일·라벨 등 기존 필드로 대응 키를 자동 생성한다.

## 가격 데이터 필수 메타데이터

모든 가격 규칙은 아래 정보를 포함해야 한다.

- 스키장 ID.
- 시즌.
- 항목 타입.
- 유효 날짜 범위.
- 요일/시기 구분.
- 시간권.
- 가격.
- 출처 URL.
- 예약/구매 URL.
- 출처 이름.
- 마지막 확인일.
- 수동 검증 여부.
- 검증 메모.
- 해석이 필요한 경우 메모.

## 비용 계산 방식

사용자가 여행 기간과 실제 스키 날짜를 입력하면 Korean Ski는 아래 순서로 비용을 계산한다.

1. 각 스키 날짜의 주중, 금요일, 주말, 공휴일, 성수기 여부를 판단한다.
2. 각 날짜의 유효 범위와 요일 조건에 적용되는 스키장·렌탈샵 가격 규칙을 찾는다.
3. 날짜마다 선택한 리프트권 시간권, 장비, 의류, 패키지와 보호장비를 매칭한다.
4. 모든 스키 날짜의 적용 항목을 합산한다.
5. 사용자가 입력한 숙박비가 있으면 합산한다.
6. 교통비를 계산한다.
7. 신뢰 가능한 가격이 없는 항목은 "가격 확인 필요"로 표시한다.
8. 트립 상세에서 사용자가 입력한 확정 금액이 있으면 해당 예상 가격을 대체한다.
9. 추가 비용을 합산한 뒤 사용자가 지정한 인원으로 동일 금액을 나눈다.

해당 날짜에 유효한 시즌 가격이 없으면 직접 고른 렌탈·할인권을 포함해 지난 시즌 가격을 자동 적용하지 않고 `가격 확인 필요`로 남긴다. 사용자는 공식 원문을 확인한 뒤 비용 화면에서 실제 금액을 입력할 수 있다.

## 포함 비용 항목

- 리프트권.
- 장비 렌탈: 리조트 공식 렌탈 및 외부 렌탈샵 가격.
- 의류 렌탈: 리조트 공식 렌탈 및 외부 렌탈샵 가격.
- 사용자가 직접 입력한 숙박비.
- 교통비.

## 렌탈 가격 범위

렌탈 가격은 아래 단위로 관리한다.

- 리조트 공식 렌탈.
- 외부 렌탈샵.
- 장비 렌탈.
- 의류 렌탈.
- 장비 + 의류 패키지.
- 스키/보드 구분.
- 성인/소인 구분.

MVP에서는 프리미엄 장비 세부 등급까지는 구분하지 않는다.

## 옵션 가격

아래 항목은 필수 비용에 포함하지 않고 옵션으로 표시한다.

- 보호장비.
- 헬멧.
- 고글.

업체별 포함 여부가 다를 수 있으므로 옵션 가격에는 출처와 메모를 남긴다.

## 교통비 계산

### 자차

```txt
왕복거리 km / 연비 * 유가 + 통행료 + 주차비
```

### 셔틀/버스

확보 가능한 노선 가격을 static 데이터로 관리한다.

### 대중교통

MVP 비용 계산에서는 제외한다.

## 가격 신뢰도

UI에서는 가격 신뢰도를 함께 표시한다.

```ts
type PriceConfidence =
  | "confirmed"
  | "estimated"
  | "phone_confirmed"
  | "unavailable";
```

- `confirmed`: 공식 페이지 또는 예약처 기준으로 개발자가 직접 확인한 가격.
- `estimated`: static 규칙으로 계산했지만 옵션에 따라 실제 결제 금액이 달라질 수 있는 가격.
- `phone_confirmed`: 전화 문의로 확인했고 마지막 확인일이 있는 가격.
- `unavailable`: 신뢰 가능한 가격을 아직 확보하지 못한 항목.

## 가격 표시 방식

가격은 최저가만 보여주지 않는다.

권장 표시:

```txt
장비 렌탈: 대표 25,000원 / 확인 범위 25,000~35,000원
```

총 예상 비용:

- 렌탈샵/옵션 선택 전: 범위로 표시.
- 렌탈샵/옵션 선택 후: 선택 옵션 기준으로 계산.

## 가격 출처 타입

허용 출처:

- 공식 웹사이트.
- 공식 예약처.
- 네이버 예약.
- 스마트스토어.
- 여행사/패키지.
- 전화 문의.

전화 문의 가격은 `phone_confirmed`로 구분하고 마지막 확인일을 반드시 기록한다.

25/26 시즌 데이터 입력 기준:

- 공식 페이지에서 텍스트 가격표를 확인한 값은 `confirmed`.
- 공식/예약처/보도자료/렌탈샵 링크는 확보했지만 가격표가 이미지, 동적 페이지, 할인 상품 중심인 경우는 `estimated`.
- 출처가 약한 값은 `verificationNote`에 재검증 필요 사유를 남긴다.

## 할인/쿠폰/패키지

- 모든 쿠폰을 추적하지 않는다.
- 대표 패키지 상품은 등록한다.
- 네이버 예약/여행사 패키지는 사용자가 실제로 많이 쓰는 경로이므로 포함할 수 있다.

## 가격 변경 감지

프로덕션 자동 감지는 만들지 않는다.

운영 흐름:

1. 시즌 중 AI에게 주요 스키장/렌탈샵 가격 변경 여부 조사를 요청한다.
2. 개발자가 공식/예약/전화 출처를 직접 검증한다.
3. static 가격 데이터를 수정한다.
4. 재배포한다.

## static 데이터 검증

가격/렌탈/스키장 데이터 수정 후 아래 명령으로 내부 정합성을 확인한다.

```bash
pnpm data:validate
pnpm data:report
```

검증 항목:

- 스키장/렌탈샵 ID 중복 여부.
- 운영 중인 스키장의 리프트권/렌탈 가격 규칙 존재 여부.
- 가격 출처 URL, 확인일, 시즌/유효기간 누락 여부.
- 렌탈샵과 가격 규칙의 스키장 참조 유효성.
- 출발지별 거리 데이터의 스키장 참조 유효성.
- 운영 스키장별 외부 렌탈샵 최소 1개 존재 여부.
- 리프트권 필수 시간권 누락 여부.
- `confirmed` 가격의 수동 검증 여부.

운영 경고 항목:

- `estimated` 가격.
- 마지막 확인일이 오래된 항목.
- 26/27 시즌 교체 대상.

CLI 보고서와 `/admin/data-quality` 전환 보드는 등록 여부만으로 완료 처리하지 않는다. 출처·기간·신뢰도가 확정됐거나 공식 이용 불가로 표시된 대응 항목만 완료율에 포함한다.

링크 상태는 수동으로 아래 명령을 실행해 확인한다.

```bash
pnpm data:links
```

## 날짜별 가격 적용

가격 규칙은 `dayType`으로 요일 조건을 가진다.

우선순위:

1. 방문 날짜와 정확히 맞는 `weekday`, `friday`, `weekend` 규칙.
2. 금요일 방문 시 `weekday` 규칙.
3. 범용 `all` 규칙.

현재 25/26 데이터에서는 모든 리조트에 `all` 가격을 넣고, 공식 요일 가격이 확인된 곳부터 `weekday`/`weekend` 규칙을 추가한다.

## 가격 출처 노출

추천 결과의 비용 요약에는 아래 정보를 함께 표시한다.

- 가격 신뢰도.
- 가격 출처명.
- 마지막 확인일.
- 출처 링크.

사용자가 렌탈샵을 고를 때는 공식 렌탈과 외부 렌탈샵을 구분하고, 옵션별 대표 가격과 출처 링크를 같이 보여준다.
