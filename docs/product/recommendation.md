# 추천 전략

## 결과 비교

- 상위 추천 3곳은 카드보다 먼저 비교표로 요약한다.
- 비교 기준은 이동 시간, 예상 비용 범위, 가격 신뢰도, 렌탈 후보 수, 핵심 추천 이유다.
- 모바일에서는 표가 화면을 깨지 않도록 명시적인 가로 스크롤 영역을 제공한다.

## 기본 접근

MVP 추천은 룰 기반으로 시작한다.

서비스가 실시간 설질, 혼잡도, 운영 상황을 알고 있는 것처럼 표현하지 않는다. 실시간 확인이 필요한 정보는 공식 스키장 페이지로 연결한다.

추천은 아래 구조로 계산한다.

```txt
하드 필터
→ 가중치 점수 계산
→ 동점 처리
→ 추천 이유 생성
```

## 입력값

사용자 입력:

- 출발지.
- 방문 날짜.
- 당일/1박 여부.
- 인원.
- 스키/보드 여부.
- 실력.
- 장비 보유 여부.
- 의류 보유 여부.
- 교통수단.
- 예산 범위.
- 추천 우선순위 1~3순위.
- 리프트권 시간권.

추천 우선순위 예시:

- 가까움.
- 저렴함.
- 초보 친화.
- 야간 가능.
- 셔틀/버스 접근성.
- 시설 좋음.
- 규모/코스 다양성.

## 출력값

추천 결과에는 아래 정보를 표시한다.

- 사용자 조건 기반 추천 스키장 3곳.
- 추천 이유.
- 예상 이동 시간.
- 필요한 예약/준비 항목.
- 방문 날짜 기준 예상 비용.
- 공식 확인 링크.
- 외부 렌탈샵 후보.
- 카테고리별 TOP 3 추천.

## 렌탈샵 추천

외부 렌탈샵 추천은 아래 요소를 함께 반영한다.

- 가격.
- 스키장과의 거리.
- 장비 렌탈 제공 여부.
- 의류 렌탈 제공 여부.
- 장비 + 의류 패키지 제공 여부.
- 픽업/배송 가능 여부.
- 수동 추천 태그.

렌탈샵/옵션 선택 전에는 비용을 범위로 보여주고, 사용자가 특정 렌탈샵과 옵션을 선택하면 선택 옵션 기준으로 총 예상 비용을 다시 계산한다.

추천 결과 화면에서는 렌탈 후보를 공식 렌탈과 외부 렌탈샵으로 구분한다.

- 공식 렌탈: 리조트 내 동선이 쉬운 옵션.
- 외부 렌탈샵: 가격 비교와 픽업 가능성을 우선 확인할 수 있는 옵션.
- 각 옵션에는 대표 가격, 신뢰도, 출처 링크를 표시한다.

## 랭킹 방식

사용자의 1순위~3순위 선호에 가중치를 준다.

예시:

```txt
1순위: 3점
2순위: 2점
3순위: 1점
```

각 스키장은 아래 점수를 가진다.

- 접근성 점수.
- 초보 친화 점수.
- 비용 점수.
- 야간 가능 점수.
- 셔틀/버스 접근성 점수.
- 가족 친화 점수.
- 규모/코스 다양성 점수.

최종 점수는 사용자의 우선순위 가중치와 필수 조건을 반영해 계산한다.

## 추천 대상 필터

기본 추천 대상은 `operating` 상태의 스키장으로 제한한다.

비시즌에는 `season_pending` 상태의 스키장을 추천 결과가 아니라 "시즌 오픈 예정" 섹션에 표시할 수 있다.

## 하드 필터

하드 필터는 필수 조건에만 적용한다.

하드 필터 항목:

- 운영 상태가 `operating`이 아닌 경우 제외.
- 사용자가 야간 스키를 필수로 선택한 경우 `nightSkiAvailable`이 false인 스키장 제외.
- 교통수단이 셔틀/버스인데 접근 가능한 노선 정보가 없는 경우 제외.

가격/운영 정보가 일부 없는 경우는 제외하지 않고 감점한다.

## 점수 카테고리

기본 점수 카테고리:

- `accessScore`: 출발지 기준 접근성.
- `beginnerScore`: 초보 친화도.
- `priceScore`: 예상 비용과 예산 적합도.
- `nightScore`: 야간 스키 가능성과 적합도.
- `transportScore`: 셔틀/버스 접근성.
- `familyScore`: 가족/동행자 친화도.
- `resortScaleScore`: 리조트 규모와 코스 다양성.
- `rentalConvenienceScore`: 공식/외부 렌탈샵 선택지와 가격 확인 가능성.

## 가격 점수

가격 점수는 아래를 함께 반영한다.

- 예상 총비용이 낮은지.
- 사용자의 예산 범위 안에 들어오는지.
- 가격 확인이 충분히 되어 있는지.

가격 미확인 항목은 추천 제외가 아니라 약한 감점으로 처리한다.

## 접근성 점수

접근성 점수는 사용자의 출발지 기준 예상 거리/시간을 사용한다.

MVP에서는 자유 입력 주소 기반 지도 API 계산이 아니라 주요 출발지 선택 방식으로 시작한다.

예시 출발지:

- 서울 강남.
- 서울 시청.
- 잠실.
- 수원.
- 인천.
- 고양.
- 성남.

## 출발지 입력

MVP 출발지는 주요 지역 선택 방식으로 제공한다.

자유 입력 주소와 지도 API 기반 시간 계산은 추후 확장으로 둔다.

## 추천 이유

추천 결과에는 내부 점수표를 직접 보여주지 않는다.

대신 추천 이유 2~3개를 보여준다.

예:

```txt
수도권 당일치기에 가깝고, 초보자 점수가 높으며, 렌탈샵 선택지가 많습니다.
```

## 카테고리별 추천

개인화 추천 3곳과 함께 아래 카테고리별 TOP 3 추천을 보여준다.

- 가까운 곳 TOP 3: 이동시간/거리 최상위.
- 저렴한 곳 TOP 3: 예상 총비용 최저.
- 초보 친화 TOP 3: `beginnerScore` 최상위.
- 야간 가능 TOP 3: 야간 운영 가능 후보 중 종합 점수 최상위.
- 교통 편한 TOP 3: `transportScore` 최상위.
- 렌탈 편한 TOP 3: `rentalConvenienceScore` 최상위.
- 1박/리조트형 TOP 3: `resortScaleScore` + 숙박 접근성.

카테고리 추천은 단일 정답처럼 보이지 않게 1~3순위 후보를 함께 노출한다.

## 동점 처리

동점 처리 순서:

1. 사용자 1순위 우선순위 항목 점수가 높은 스키장.
2. 접근성이 좋은 스키장.
3. 예상 비용이 낮은 스키장.

## 추천 결과 개수

- 기본 추천 결과는 3개.
- 사용자가 원하면 전체 보기 옵션을 제공한다.

## 추천 점수 노출

내부 점수는 사용자에게 직접 노출하지 않는다.

사용자에게는 아래를 우선 보여준다.

- 추천 이유.
- 예상 비용.
- 이동 시간.
- 필요한 예약/준비 항목.
- 공식/예약/렌탈 링크.

## 추천 스냅샷 저장

추천 후보 전체를 저장하지 않는다.

사용자가 선택한 추천 결과의 스냅샷만 트립에 저장한다.

## 예시 룰

```txt
초보 + 수도권 출발 + 당일치기 + 렌탈 필요
=> 접근성, 초보 친화, 렌탈 정보 제공 여부, 단순한 일정 구성을 우선한다.
```
