# 스키장 데이터셋 정책

하이원리조트의 25/26 렌탈·리프트·공식 숙박 상세 기준과 출처는 [하이원 25/26 데이터셋](./high1-25-26-dataset.md)에서 관리한다.

전체 스키장의 25/26 공식 렌탈·숙박과 외부 렌탈샵 조사 기준은 [25/26 전국 공급자 데이터셋](./season-25-26-provider-dataset.md)에서 관리한다.

## 기본 방향

설레일은 일부 유명 스키장만 다루지 않고 국내 스키장 전체를 데이터셋에 포함한다.

운영 중인 스키장만 보여주는 것이 아니라, 휴장/폐장 상태도 구분해서 사용자가 검색했을 때 현재 상태를 알 수 있게 한다.

2026년 5월 기준 MVP 데이터셋에서는 베어스타운을 제거한다. 사용자가 요청한 초기 운영 범위는 베어스타운을 제외한 국내 스키장 13곳이며, 베어스타운은 운영 재개/공식 가격 확인 전까지 디렉토리와 추천 대상에 포함하지 않는다.

## 포함 범위

- 운영 중인 국내 스키장.
- 시즌 오픈 예정 스키장.
- 임시 휴장 스키장.
- 폐장 스키장.
- 상태 확인이 필요한 스키장.

## 기본 노출 정책

- 운영 중/시즌 오픈 예정 스키장을 기본 노출한다.
- 휴장/폐장 스키장은 기본 추천 대상에서 제외하되, 디렉토리에서 필터나 상태 표시로 확인 가능하게 한다.

## 운영 상태

```ts
type OperationStatus =
  | "operating"
  | "season_pending"
  | "temporarily_closed"
  | "closed"
  | "unknown";
```

## 추천 대상 정책

- 기본 추천 대상은 `operating` 상태의 스키장으로 제한한다.
- 비시즌에는 `season_pending` 상태의 스키장을 "시즌 오픈 예정" 섹션에 표시할 수 있다.
- `temporarily_closed`, `closed`, `unknown` 상태는 추천 대상에서 제외한다.

## 저장 방식

- 스키장 데이터는 DB가 아니라 static 코드 데이터로 관리한다.
- 시즌 시작 전 AI 조사와 개발자 검증을 거쳐 static 데이터에 반영한다.
- 시즌 중 변경이 확인되면 코드 수정 후 재배포한다.

## 지도 링크

스키장 비교 화면은 Kakao Maps JavaScript API가 설정된 경우 실제 지도를 제공한다.

- 스키장 위치는 정적 좌표 데이터로 관리한다.
- 좌표는 공식 주소와 지도 검색 결과를 기준으로 수동 검증해 반영한다.
- 스키장 디렉토리에서는 지도 중심 화면 위에 스키장 핀을 표시하고, 왼쪽 리스트 선택과 지도 선택 상태를 동기화한다.
- 스키장 디렉토리에서 주변 더 둘러보기를 열면 렌탈샵/숙박 후보 핀을 지도에 표시하고, 핀 선택 시 해당 장소 정보를 카드로 보여준다.
- 스키장 상세에서는 별도 지도를 반복하지 않고 스키장 매력, 추천 대상, 공식 코스·운영 링크, 가격 출처와 트립 생성 CTA를 우선한다.
- 실제 길찾기, 리뷰, 영업시간 확인은 네이버 지도/카카오맵 외부 링크로 연결한다.
- Kakao Maps JavaScript API 키가 없거나 로드에 실패하면 임의 좌표 지도를 만들지 않고 정확한 외부 지도 링크와 목록 비교를 제공한다.
- 주변 장소 마커는 임의 오프셋을 사용하지 않는다. 주소가 있는 업체는 주소 검색, 공식 숙박은 장소명 검색 결과가 확인된 경우에만 표시한다.

## 예약 링크

예약 링크는 아래 범위를 포함할 수 있다.

- 리조트 공식 사이트.
- 리조트 공식 예약처.
- 네이버 예약.
- 여행사/패키지 상품 링크.

단, 링크 출처와 마지막 확인일을 기록한다.

## 렌탈샵 정보

MVP에서는 리조트 공식 렌탈뿐 아니라 외부 렌탈샵 정보도 수동 등록한다.

목표:

- 사용자가 렌탈샵을 일일이 찾아보고 가격을 비교하는 수고를 줄인다.
- 시즌별로 검증한 가격과 링크를 제공한다.

포함 가능 정보:

- 렌탈샵 이름.
- 장비 렌탈 가능 여부.
- 의류 렌탈 가능 여부.
- 장비 + 의류 패키지 여부.
- 위치/지도 링크.
- 가격 페이지 또는 예약 링크.
- 픽업/배송 가능 여부.
- 수동 추천 태그.
- 마지막 확인일.

## 숙박 정보

MVP 숙박 정보는 우선 리조트 공식 객실/콘도 링크를 기본 후보로 제공한다.

포함 가능 정보:

- 숙박명.
- 공식 객실/콘도 링크.
- 위치/지도 링크.
- 스키장 기준 예상 이동 시간.
- 마지막 확인일.
- 리조트 숙소와 호텔 유형.
- 공식 객실 판매 상태, 조건·적용 기간·출처가 명시된 공개 요금 스냅샷.

숙박 판매 현황의 static 데이터는 `src/data/official-lodging-sales.ts`에서 관리한다. 특정 날짜의 재고와 최종 금액은 보장하지 않으며 공식 예약 화면에서 확인한다. 사용자가 입력한 실제 숙박비만 트립 비용에 반영한다.

외부 숙박업소는 자동 수집하지 않는다. NOL·여기어때 등 예약처의 개별 숙소 페이지를 확인해 리조트 공식 숙소와 분리된 수동 후보로 static 데이터에 추가한다. 예약처, 직접 예약 URL, 출처 URL, 마지막 확인일을 기록하고, 스키장까지의 이동 시간은 예약 페이지에 명시된 경우에만 표시한다. 날짜와 인원에 따라 바뀌는 가격·재고는 static 값으로 기록하지 않고 예약 페이지에서 확인하도록 연결한다.

## 강습 정보

강습 정보는 1차 MVP에서 제외한다.

제외 항목:

- 강습 가격 비교.

## 가격 데이터 없는 경우

가격 데이터가 없는 스키장이나 렌탈샵도 노출할 수 있다.

## 스키장 상세 화면

스키장 상세 화면은 내부 점수를 노출하지 않는다. 동일한 구조의 추천 대상·코스 안내·풍경·가격 출처를 제공하고, 실제 코스 운영 정보는 공식 링크에서 최종 확인하도록 한다.

포함 정보:

- 운영 상태, 야간 가능 여부, 태그.
- 리프트권 가격과 출처 링크.
- 공식 렌탈과 외부 렌탈샵 후보.
- 공식 사이트, 운영현황, 리프트권, 렌탈, 지도 링크.

표시 방식:

```txt
가격 확인 필요
```

데이터 누락만으로 추천 후보를 숨기지 않는다.

## 검증 방식

데이터 갱신 흐름:

1. AI로 공식/예약/렌탈샵 후보 링크를 조사한다.
2. 개발자가 직접 출처를 확인한다.
3. static 데이터에 반영한다.
4. 재배포한다.
