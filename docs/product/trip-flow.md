# 트립 생성 플로우

## 기본 흐름

추천 기반 흐름:

```txt
홈
→ 조건 입력
→ 추천 결과
→ 스키장/렌탈 옵션 선택
→ 트립 생성
→ 트립 상세/체크리스트
```

직접 선택 흐름:

```txt
스키장 탭/상세
→ 이 스키장으로 트립 만들기
→ 스키장 고정 조건 입력
→ 트립 생성
→ 트립 상세/체크리스트
```

로그인은 선택 사항이다. 비로그인 사용자는 바로 트립을 만들 수 있고, 로그인 사용자는 만든 트립이 "내 트립" 목록에 저장된다.

## 저장 시점

트립은 사용자가 스키장을 선택하고 "트립 만들기"를 클릭하는 시점에 DB에 저장한다.

정책:

- 조건 입력 시작 시점에는 서버에 저장하지 않는다.
- 추천 결과 표시 시점에도 서버에 저장하지 않는다.
- 서버에 트립 생성 전 초안을 저장하는 기능은 MVP에서 제외한다. 단, 비로그인 사용자가 생성 직전 로그인을 선택하면 현재 탭의 `sessionStorage`에 입력값을 최대 24시간 임시 보관한다.
- 로그인 사용자가 트립을 생성하면 계정에 즉시 연결한다.
- 비로그인 사용자가 트립을 생성하면 edit link를 발급하고, 이후 로그인 시 계정에 연결할 수 있다.
- 비로그인 사용자가 추천 결과에서 트립 생성을 시도하면 저장 전 확인 dialog를 표시한다.
  - 로그인 후 생성하면 내 트립 목록에서 다시 확인할 수 있고, 현재 입력값을 유지한 채 로그인 화면을 왕복함을 안내한다.
  - 비로그인으로 계속하면 편집 링크를 직접 저장해야 하며, 링크를 잃으면 복구하기 어렵다는 점을 명확히 안내한다.
  - 사용자는 dialog에서 `현재 설정 그대로 로그인`을 선택하거나, 경고를 확인하고 `로그인 없이 링크로 만들기`를 선택할 수 있다.
  - 로그인 완료 후 동일한 생성 URL과 동일한 스키장 폼에만 초안을 복원하고 마지막 확인 단계로 돌아온다. 사용자가 최종 생성 버튼을 누르기 전에는 트립을 자동 생성하지 않는다.

## 로그인/내 트립 흐름

### 비로그인 사용자

```txt
트립 생성 클릭
→ 비로그인 생성 경고 dialog
→ 비로그인으로 계속
→ edit link 발급
→ 트립 상세에서 "로그인하고 내 트립에 저장" CTA 표시
→ 로그인 완료
→ 해당 트립을 계정에 연결
→ 내 트립 목록에서 접근 가능
```

### 로그인 사용자

```txt
로그인
→ 트립 생성
→ userId가 연결된 트립 저장
→ `/my-trips/{tripId}` 소유자 화면으로 즉시 이동
→ 내 트립 목록에서 재접근
```

로그인 소유자가 이전 익명 편집 주소(`/trips/{editToken}`)로 접근해도 소유자 화면으로 정규화한다. 생성 직후와 재접근 시 권한 배너·공유 관리 노출이 달라지지 않아야 한다.

### 내 트립 목록

- 전체/내 다가오는 트립/내 지난 트립/공유된 트립 개수를 요약해서 표시한다.
- 다가오는 트립을 먼저 표시한다.
- 지난 트립은 별도 섹션으로 구분한다.
- 계정 초대로 참여한 트립은 `공유된 트립` 섹션으로 분리하고 보기/편집 권한을 표시한다.
- 팀 멤버십에서 확인된 동행자 이름을 카드와 상세에 배지로 표시한다. 전체 이메일 주소는 카드에 노출하지 않는다.
- 사용자는 트립 이름을 자유롭게 수정할 수 있다. 이름이 없으면 `스키장명 트립`으로 표시한다.
- 각 트립 카드에는 방문 날짜, 인원, 교통수단, 체크리스트 완료 개수, 준비 진행률을 표시한다.
- 공유 링크가 아니라 본인 편집 권한으로 트립 상세에 진입한다.
- 트립 상세는 `개요`, `렌탈샵 & 리프트`, `숙박`, `교통`, `체크리스트`, `비용·정산` 작업 공간으로 나눈다. 개요는 확정된 렌탈·리프트·교통·숙소를 요약하고 체크리스트의 결정형 항목은 해당 선택 탭으로 직접 연결한다.
- 트립 이름은 상단에서 바로 수정하고 날짜·인원·상태는 `여행 기본 설정`에서 관리한다.

## 조건 입력 단계

조건 입력은 모바일 우선 2단계 진행형 폼으로 구성한다. 날짜·이동 계산 기준 지역·인원과 스키 실력·종목·보유 장비를 기본 입력으로 받고, 예산·추천 우선순위·리프트 이용 시간·숙박비는 접힌 선택 설정으로 둔다.

정책:

- 한 화면에는 현재 단계의 입력만 보여준다.
- 사용자는 "다음 단계"로 순차 진행하며, 이전 단계로 돌아가 수정할 수 있다.
- 아직 도달하지 않은 다음 단계로는 직접 점프할 수 없다.
- 상단에는 현재 단계, 전체 단계 수, 진행률을 명확히 표시한다.
- 단계 전환은 짧고 가벼운 모션을 사용하되 입력을 방해하지 않는다.
- 방문 날짜처럼 추천에 필수인 값은 다음 단계로 넘어가기 전에 확인한다.
- 추천의 기본값은 초보, 스키, 장비와 의류 렌탈 필요, 4시간 이용으로 둔다. 사용자는 별도 입력 없이 기본값으로 진행할 수 있다.
- 예산·선호 순위·리프트 이용 시간은 기본 입력 없이 추천을 볼 수 있도록 접힌 선택 설정으로 제공한다.
- `/plan?resortId=...`로 진입하면 스키장을 고정한 직접 선택 모드로 표시한다.
  - 직접 선택 모드는 추천 결과 페이지를 거치지 않고 두 번째 단계에서 바로 트립을 생성한다.
  - 비로그인 사용자는 추천 결과와 동일한 저장 전 경고 dialog를 본다.
  - 상단에는 선택된 스키장명을 표시해 추천 비교가 아니라 고정 스키장 트립 생성임을 명확히 한다.
- 상단 내비게이션의 `/plan` 라벨은 "트립 추천"으로 두고, 스키장 탭/상세에서는 "이 스키장으로 트립 만들기" CTA로 직접 선택 흐름을 시작한다.

### 1단계: 여행 정보

- 방문 날짜.
- 이동 계산 기준 지역. 주요 도시의 대표 지점을 사용하고, 이동 시간과 자차 교통비는 실시간 교통이 반영되지 않은 대략적인 추정치로 안내한다.
- 인원.
- 당일/1박 여부.
- 교통수단: 자차, 대중교통. 대중교통에는 버스·기차·리조트 제휴 셔틀이 포함된다.

### 2단계: 스키 준비와 선택 설정

- 실력: 처음, 초보, 중급, 상급.
- 스키/보드 여부.
- 장비 보유 여부.
- 의류 보유 여부.

- 선택 설정: 예산 범위, 추천 우선순위 1~3순위, 리프트 이용 시간, 숙박비 직접 입력.
- 별도 확인 단계 없이 두 번째 단계에서 추천 결과 또는 고정 스키장 트립으로 진행한다.

## 추천 결과

추천 결과에서는 아래 정보를 보여준다.

- 사용자 조건 기반 추천 스키장 3곳.
- 항목별 예상 비용 요약.
- 총 예상 비용 범위.
- 추천 이유.
- 필요한 예약/준비 항목.
- 공식/예약/렌탈 링크.
- 추천 카드 안에서 같은 날짜·인원·교통 조건으로 계산한 리조트 공식 렌탈과 주변 렌탈샵 가격 구성을 비교한다.
- 리프트권, 장비·의류, 교통, 숙박 항목을 구분하고 일행 전체와 1인 예상액을 함께 표시한다.
- 해당 날짜에 적용 가능한 가격 자료가 있는 외부 샵 후보 가운데 낮은 대표 예상액을 비교 대상으로 선택한다. 외부 샵의 할인 리프트권이 적용 가능하면 해당 금액을 사용한다.
- 가격이 없는 경우 임의 금액을 비교하지 않고 원문과 주변 샵 탐색 경로를 안내한다.

가격 출처는 각 비용 항목과 연결한다. 추천 결과에서는 상위 추천 1곳의 비교 내용을 펼쳐 보여주고 나머지 추천은 사용자가 필요할 때 펼친다.

## 스키장/렌탈 옵션 선택

추천 카드에서 비용 구성을 먼저 비교하고 바로 트립을 만들 수 있다. 이때 렌탈샵을 확정하지 않아도 된다.

흐름:

1. 추천 결과에서 리조트 공식 이용과 주변 렌탈샵 이용의 가격 구성을 비교한다.
2. 원하는 스키장의 트립을 만든다.
3. 트립의 `스키 일정 & 렌탈` 작업공간에서 실제 스키 날짜와 날짜별 렌탈샵·품목을 확정한다.

## 렌탈샵 선택 정책

- 렌탈샵 선택은 필수가 아니다.
- 선택 전 총액은 가격 범위로 표시한다.
- 장비, 의류, 보호·추가 장비는 별도 품목으로 선택하고 `장비 + 의류` 결합 상품이 더 저렴하면 패키지 절감액을 안내한다.
- 날짜별로 다른 렌탈샵과 품목을 선택할 수 있다. `다른 스키 날짜에도 적용`을 선택하면 같은 샵·품목에서 각 날짜의 이용 시간에 맞는 상품을 우선 연결한다.
- 렌탈샵/옵션을 선택하면 모든 스키 날짜의 선택 옵션을 합산해 총 예상 비용을 다시 계산한다.

## 여행 기간과 스키 날짜

- 트립은 도착 날짜 `visitDate`와 출발 날짜 `endDate`를 구분한다. 기간은 최대 14일이다.
- 숙박 기간의 모든 날짜를 스키 날짜로 단정하지 않는다. 사용자가 기간 안에서 실제 스키를 탈 날짜를 하나 이상 선택한다.
- 각 스키 날짜는 독립적인 이용 시간, 렌탈샵, 장비, 의류, 보호장비, 리프트권 선택을 가진다.
- 당일치기는 도착일과 출발일이 같고 단일 스키 날짜를 기본값으로 사용해 기존의 짧은 흐름을 유지한다.
- 기존 단일 날짜·렌탈 데이터는 첫 스키 날짜 계획으로 자동 해석한다.

## 숙박비 정책

- 숙박비는 조건 입력 단계에서 직접 입력할 수 있다.
- 입력하지 않아도 트립 생성은 가능하다.
- 트립 상세에서 나중에 입력하거나 수정할 수 있다.
- 트립 상세에서 숙소명과 예약 링크도 기록할 수 있다.
- 플랫폼은 주변/공식 숙박 탐색 링크를 제공하지만 숙박 가격과 재고를 수집하거나 보장하지 않는다.

## 선택 이후 비용·정산

- 리프트 시간권, 렌탈샵/상품, 교통과 숙소 변경은 각 선택·예약 작업공간에서 처리하며, 비용 화면은 현재 선택 요약과 이동 링크를 제공한다.
- 선택·예약 작업공간에서 선택을 변경하면 현재 static 시즌 데이터로 예상 비용 snapshot을 갱신한다.
- 실제 결제 금액이 다르면 항목별로 직접 확정 금액을 입력한다.
- 식비, 주유, 통행료, 주차 등 추가 비용을 더하고 총액을 정산 인원으로 동일하게 나눈다.
- 직접 입력한 금액은 이후 static 데이터 갱신보다 우선한다.

## 리프트권 시간권

- 트립 생성 전에는 대표 리프트권 시간권을 선택한다.
- 트립 생성 후에는 실제 스키 날짜마다 시간권을 다르게 설정할 수 있으며 날짜별 가격 계산에 사용한다.

## 체크리스트 생성

트립 생성 시 모든 기본 체크리스트 항목을 생성한다.

조건에 따라 필요 없는 항목은 삭제하지 않고 `not_needed` 상태로 표시한다.

이유:

- 사용자가 "내가 이걸 챙겼나?"를 전체 목록 기준으로 확인할 수 있게 하기 위해.
- 초보자가 놓치기 쉬운 항목을 숨기지 않기 위해.

## 트립 수정 정책

트립 생성 후 아래 값을 수정할 수 있다.

- 도착·출발 날짜와 실제 스키 날짜.
- 인원.
- 교통수단.
- 날짜별 렌탈샵과 장비·의류·추가 장비.
- 숙박비.
- 리프트권 시간권.

수정 후에는 현재 static 가격 데이터 기준으로 비용 스냅샷을 다시 계산한다.

스키장, 실력, 장비/의류 보유 여부 변경은 추천/체크리스트 영향이 크므로 후속 작업에서 별도 변경 플로우로 제공한다.

트립 상태는 사용자가 수동으로 `planning`, `ready`, `completed`, `archived` 중 선택할 수 있다.

## 생성 완료 후 화면

트립 생성 후 바로 트립 상세 화면으로 이동한다.

트립 상세 상단에는 안내 배너를 표시한다.

배너 내용:

- 비로그인 상태에서는 편집 링크를 가진 사람은 트립을 수정할 수 있음.
- 비로그인 상태에서는 로그인 후 내 트립에 저장할 수 있음.
- 로그인 상태에서는 내 트립에 저장됨.
- 공유 관리는 보기/편집 링크 발급·개별 폐기와 가입 사용자 초대를 한곳에서 제공함.

트립 상세에는 아래 정보를 함께 표시한다.

- 예상 총액과 항목별 비용.
- 리프트권/렌탈 가격 출처와 신뢰도. 확인일은 내부 데이터 품질 관리에만 사용한다.
- 선택한 렌탈 옵션.
- 현재 static 가격과 생성 당시 가격이 달라졌을 가능성이 있으면 안내.
- 리프트권 공식 확인 링크.
- 렌탈샵 예약/확인 링크.
- 네이버 지도와 공식 운영현황 링크.

체크리스트 영역은 상단에 "이번 트립 준비" 요약을 제공하고, 카테고리별 완료 개수를 함께 표시한다.

예약/준비 체크리스트 항목에는 가능한 경우 바로 이동할 수 있는 외부 링크를 붙인다.

## 트립 상세 정보 구조

- 트립명, 스키장, 날짜, 인원, 상태, 관리 메뉴와 공식 링크를 담은 상단 요약은 `트립 개요`에서만 표시한다. 다른 작업공간은 이 요약을 반복하지 않고 선택한 기능의 콘텐츠부터 보여준다.
- 본문은 `트립 개요`, `준비 체크리스트`, `비용·정산`으로 분리한다.
- 데스크톱에서는 현재 트립 안에서만 사용하는 왼쪽 사이드바로 전환한다.
- 모바일에서는 같은 항목을 상단 탭으로 제공하며 한 화면에는 선택한 기능만 렌더링한다.
- 모바일 탭은 현재 항목이 항상 보이도록 자동 정렬하고, 사용자가 탭을 바꾸면 새 작업공간의 시작과 제목으로 이동한다.
- URL의 `view` query로 현재 작업공간을 표현해 새로고침과 공유 후에도 같은 기능으로 돌아올 수 있게 한다.
# 트립 UX 보강

- 로그인 사용자는 기존 트립을 복제할 수 있다.
- 복제 시 일정, 선택 옵션과 체크 항목별 메모는 유지하고 완료 상태는 `needs_check`로 초기화한다. 트립 자체 메모는 복제하지 않는다.
- 사용자 추가 체크 항목은 이름과 메모를 수정하고 삭제할 수 있다.
- 기본 체크 항목은 이름과 삭제를 제한하지만 메모는 수정할 수 있다.
- 수정, 공유, 복제, 삭제는 본문 카드가 아니라 상단 `트립 관리` 메뉴 안에 배치한다.
- 성공한 생성·수정·상태 변경·추가·삭제 액션은 Sonner 토스트로 즉시 알려준다.
