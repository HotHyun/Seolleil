# UI 디자인 방향

## 확정 스택

- Styling: Tailwind CSS.
- UI components: shadcn/ui.
- Icons: lucide-react.
- Form handling: react-hook-form + zod.

## 제품 톤

Korean Ski의 UI는 설원으로 떠나는 기대감을 만드는 랜딩 경험과 실용적인 트립 플래너를 연결한다. 랜딩의 감성은 계획 진입을 늦추지 않아야 하며, 운영 화면은 계속 밀도 높고 실용적으로 유지한다.

목표:

- 조건 입력이 쉽다.
- 추천 결과 비교가 빠르다.
- 예상 비용과 준비 상태가 한눈에 보인다.
- 체크리스트 업데이트가 모바일에서 불편하지 않다.

## 시각 스타일

- 라이트/다크 테마를 모두 지원한다.
- 전 화면은 로컬 Pretendard Variable로 통일한다.
- 라이트 테마: 스노우 화이트/미드나이트 기반 + 코발트 액션.
- 다크 테마: 딥 미드나이트 기반 + 밝은 코발트 액션.
- 라임은 랜딩 CTA, 완료, 기대감을 나타내는 제한적 보조 액센트로 사용한다.
- 스키/겨울 서비스에서 흔한 블루 일변도 팔레트는 피한다.
- 주요 CTA, 강조 배지, 진행률에는 현재 테마의 `primary` 토큰을 사용한다.
- 정보 밀도는 높이되, 초보자가 부담스럽지 않게 섹션을 명확히 나눈다.

## 레이아웃

### 스키장 지도 탭

- 스키장 탭의 기본 화면은 카드 디렉토리가 아니라 지도 중심 탐색 화면으로 구성한다.
- 데스크톱에서는 왼쪽에 스키장 리스트/검색 사이드바를 두고, 오른쪽 전체 영역을 지도에 할당한다.
- 사용자가 왼쪽 스키장 카드를 선택하면 지도 중심이 해당 스키장으로 이동하고 선택 상태가 명확히 표시되어야 한다.
- 선택된 스키장 패널에는 핵심 점수, 렌탈/숙박 후보 수, 상세 진입, 주변 더 둘러보기 액션을 제공한다.
- 주변 더 둘러보기는 선택된 스키장 근처의 렌탈샵과 숙박 후보를 먼저 보여주고, 실제 길찾기/지도 확인은 외부 지도 링크로 연결한다.
- 주변 더 둘러보기 상태에서는 왼쪽 사이드바가 스키장 목록에서 주변 숙박/렌탈 목록으로 전환되고, 상단에 스키장 목록으로 돌아가는 액션을 제공한다.
- 지도 위 선택 카드와 주변 장소 카드는 투명/글래스 스타일보다 현재 테마의 불투명 카드 배경을 사용한다.
- 모바일에서는 사이드바와 지도 영역을 세로로 쌓되, 지도와 선택 패널을 먼저 이해할 수 있어야 한다.

### 홈 첫 화면

- 첫 화면은 실제 스키 이미지 위에 어두운 마스크 레이어를 올린 풀블리드 히어로로 구성한다.
- 히어로에는 제품 스크린샷이나 긴 설명문을 두지 않고, 핵심 가치 문장과 주요 CTA만 배치한다.
- 히어로 하단에는 운영 스키장 수, 날짜 기준 비용, 공유 체크리스트처럼 즉시 이해되는 짧은 지표를 배치할 수 있다.
- 히어로 아래 랜딩 섹션은 추천, 비용, 체크리스트, 공유 흐름을 기능 단위로 보여준다.
- 데스크톱에는 실제 추천·비용·준비 흐름을 압축한 플래너 미리보기를 노출한다.
- 장시간 스크롤 고정이나 강제 패럴랙스를 사용하지 않는다. CSS 기반 진입/부유 모션을 사용하고 `prefers-reduced-motion`을 준수한다.

### 모바일

- 1열 흐름을 기본으로 한다.
- 조건 입력 → 추천 결과 → 트립 상세 → 체크리스트 순서가 자연스럽게 이어져야 한다.
- 폼은 긴 단일 페이지보다 단계별/섹션별 입력이 적합하다.
- 체크리스트 상태 변경은 한 손 조작이 가능해야 한다.

### 데스크톱

- 모바일 1열 구조를 기반으로 2열 레이아웃으로 확장한다.
- 내비게이션은 사이드바가 아니라 상단 헤더 하나로 유지한다.
- 추천 결과 화면에서는 추천 카드와 비용/필요 항목 요약을 나란히 보여줄 수 있다.
- 트립 상세 화면에서는 일정/링크와 체크리스트를 분리해 보여줄 수 있다.

## 컴포넌트 원칙

- 버튼, 카드, 탭, 다이얼로그, 토스트, 폼 필드는 shadcn/ui 스타일을 우선 사용한다.
- Select와 Date Picker는 native control이 아니라 shadcn/Radix 기반 컴포넌트를 사용한다.
- 아이콘은 lucide-react를 사용한다.
- 조건 입력 폼은 react-hook-form + zod로 검증한다.
- 숫자 입력, 선택 옵션, 우선순위 선택은 모바일에서 터치하기 쉬운 컨트롤을 사용한다.
- 외부 링크 버튼에는 외부 링크 아이콘을 함께 표시한다.

## 디자인 시스템 문서

세부 디자인 토큰, 컴포넌트 원칙, 페이지별 가이드는 `docs/design.md`를 기준으로 한다.

## 지도 정책

MVP에서는 지도 API를 직접 연동하지 않는다.

- 네이버 지도 외부 링크.
- 카카오맵 외부 링크.

## 시각화 정책

MVP에서는 복잡한 차트를 만들지 않는다.

표시할 요약:

- 총 예상 비용.
- 비용 항목별 금액.
- 준비 진행률.
- 예약/확인 필요 항목 수.

## 접근성/사용성

- 주요 CTA는 모바일에서 엄지 영역에 배치한다.
- 가격, 날짜, 상태값은 텍스트만이 아니라 시각적 구분을 함께 제공한다.
- 색상만으로 상태를 구분하지 않는다.
- 외부 링크 이동은 사용자가 명확히 인지할 수 있어야 한다.
