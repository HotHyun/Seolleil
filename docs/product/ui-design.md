# UI 디자인 방향

## 확정 스택

- Styling: Tailwind CSS.
- UI components: shadcn/ui.
- Icons: lucide-react.
- Form handling: react-hook-form + zod.

## 제품 톤

설레일의 UI는 설원으로 떠나는 기대감을 만드는 랜딩 경험과 실용적인 트립 플래너를 연결한다. 랜딩의 감성은 계획 진입을 늦추지 않아야 하며, 운영 화면은 계속 밀도 높고 실용적으로 유지한다.

목표:

- 조건 입력이 쉽다.
- 추천 결과 비교가 빠르다.
- 예상 비용과 준비 상태가 한눈에 보인다.
- 체크리스트 업데이트가 모바일에서 불편하지 않다.
- 스키장 비교 지도에서는 점수 대신 설명형 태그, 렌탈·숙박 후보 수와 실제 이동 정보를 사용한다.
- 스키장 상세는 별도 지도를 반복하지 않고 추천 대상, 코스 확인, 풍경, 가격 출처와 트립 생성 전환에 집중한다.
- 계정 트립 상세 최상단에는 내 트립 목록으로 돌아가는 직접적인 뒤로 가기 동작을 둔다.

## 시각 스타일

- 라이트/다크 테마를 모두 지원한다.
- 전 화면은 로컬 Pretendard Variable로 통일한다. 웨이트는 400·500·600만 쓴다.
- 표면·테두리·글자는 하나의 쿨 뉴트럴 램프에서 가져오고, 액센트는 코발트(`primary`) 하나로 주요 버튼·선택·링크·진행률에만 쓴다.
- 라임은 완료 상태 같은 제한적 용도에만 쓰고 표면이나 버튼에는 쓰지 않는다.
- 색조 그라데이션, 글로우, 색 그림자, 그라데이션 텍스트, 반복·부유 모션을 쓰지 않는다.
- 설레일의 시그니처는 가격 옆의 신뢰도 점이다. 채운 점은 확인, 빈 점은 추정·미확인이며 모든 가격 옆에 둔다.
- 정보 밀도는 높이되, 초보자가 부담스럽지 않게 섹션을 명확히 나눈다.

## 레이아웃

### 스키장 지도 탭

- 스키장 탭의 기본 화면은 카드 디렉토리가 아니라 지도 중심 탐색 화면으로 구성한다.
- 데스크톱에서는 왼쪽에 스키장 리스트/검색 사이드바를 두고, 오른쪽 전체 영역을 지도에 할당한다.
- 사용자가 왼쪽 스키장 카드를 선택하면 지도 중심이 해당 스키장으로 이동하고 선택 상태가 명확히 표시되어야 한다.
- 선택된 스키장 패널에는 이해하기 어려운 내부 점수를 노출하지 않고 설명형 특징, 렌탈/숙박 후보 수, 상세 진입, 주변 더 둘러보기 액션을 제공한다.
- 렌탈/숙박 후보 수의 아이콘과 텍스트는 같은 좌측 정렬축을 사용하고, 아이콘을 텍스트 위 중앙 장식으로 배치하지 않는다.
- 주변 더 둘러보기는 렌탈·숙박·픽업·가격 확인 필터를 제공하고, 실제 위치는 Kakao Map 또는 정확한 외부 지도 링크로 확인한다.
- Kakao Map 키가 없거나 로드에 실패하면 임의 좌표 기반 장식 지도를 보여주지 않고 설정 안내와 외부 지도 링크를 제공한다.
- 주변 더 둘러보기 상태에서는 왼쪽 사이드바가 스키장 목록에서 주변 숙박/렌탈 목록으로 전환되고, 상단에 스키장 목록으로 돌아가는 액션을 제공한다.
- 지도 위 선택 카드와 주변 장소 카드는 투명/글래스 스타일보다 현재 테마의 불투명 카드 배경을 사용한다.
- 모바일에서는 검색과 스키장 목록(최대 높이 제한, 내부 스크롤)을 먼저 보여주고 그 아래에 지도와 선택 패널을 쌓는다. 목록에서 스키장을 고르면 지도로 스크롤한다.
- 모바일 선택 패널은 지도 내부를 크게 가리는 전체 오버레이로 두지 않는다. 지도 아래에 배치하고 상단만 약 40px 겹치는 시트 형태로 제공한다.
- 모바일 지도는 선택 패널을 제외하고 최소 460px의 조작 가능한 높이를 확보하며, 선택 패널에서는 주소와 부가 태그를 축약한다.

### 홈 첫 화면

- 첫 화면은 화면 높이를 채우는 분할 구성이다. 왼쪽은 페이지 배경 위의 헤드라인·설명·빠른 시작 폼이고, 오른쪽 약 60%는 스키 사진이다. 사진의 왼쪽 가장자리는 배경으로 녹이고 어두운 오버레이는 쓰지 않는다.
- 헤드라인은 제품이 하는 일을 직접 말한다("국내 스키장, 이동 시간과 총비용으로 비교해요"). 헤드라인 위 배지, 체크 문구 줄, 두 번째 버튼은 두지 않는다.
- 주 행동은 방문 날짜와 출발지만 고르면 기본 조건(2명·당일·자차·초보)으로 `/recommendations`에 이동하는 미니 폼이다. 보조 행동은 `/plan`으로 가는 조용한 링크 하나다.
- 결과 카드는 추천 엔진이 계산한 샘플 여행(강남 출발·2명·당일)의 실제 값과 신뢰도 점을 보여 주며, 계산 실패 시 고정 예시로 대체한다. 데스크톱에서는 사진 하단 경계에 걸치고 모바일에서는 폼 아래에 쌓인다.
- 히어로 바로 아래에는 수록 스키장 수, 수록 렌탈샵 수, 최근 가격 확인일을 정적 데이터에서 계산한 데이터 띠로 표시한다. 렌탈샵 수에는 목록만 있는 업체가 포함되므로 "수록"으로 표기한다.
- 그 아래에는 가격 신뢰도, 체크리스트 진행률, 공유 링크를 폭이 다른 세 타일로 보여 준다. 순서가 아닌 병렬 기능이므로 번호 카드를 쓰지 않는다.
- 이어서 FAQ 아코디언(`<details>`)과 단색 최종 CTA 띠를 둔다.
- 예시 가격은 기준 시즌과 예시임을 밝히며, 임의의 추천 점수나 진행률을 실제 결과처럼 표시하지 않는다.
- 진입 모션은 첫 로드에 한 번 짧은 페이드와 12px 상승뿐이다. 스크롤 고정, 패럴랙스, 반복 모션은 쓰지 않으며 `prefers-reduced-motion`을 준수한다.

### 추천 결과 화면

- 비교표를 카드 위에 두고 1순위 열만 은은하게 강조한다. 안내(기본 조건, 개장 전 제외, 가격 시즌)는 색 박스 대신 한 줄 문구로 쓴다.
- 1순위는 전체 카드로 보여 주고(총액은 오른쪽 패널에 한 번만, 신뢰도 점과 함께), 2·3순위는 이름·이동·예상 총액·가격 신뢰도를 담은 요약 행으로 접어 두었다가 펼치면 전체 카드를 보여준다.
- 비교표는 모바일에서 첫 열을 고정(sticky)하고 오른쪽 가장자리에 그라데이션으로 가로 스크롤 가능함을 알린다.
- 가격 신뢰도는 `ConfidenceBadge`/`ConfidenceDot`(`src/components/confidence-badge.tsx`)로만 표시한다. 확인됨·전화확인은 채운 점, 추정·확인필요는 빈 점이며 설명은 툴팁과 스크린리더 텍스트로 제공한다.
- 보조 문구 최소 글자 크기는 12px(`text-xs`)이며 본문 설명은 14px 이상을 사용한다.

### 로그인 화면

- 로그인/가입 폼 아래에 "로그인 없이 트립 만들기" 보조 링크를 두어 익명 흐름으로 돌아갈 수 있게 한다.

### 모바일

- 1열 흐름을 기본으로 한다.
- 조건 입력 → 추천 결과 → 트립 상세 → 체크리스트 순서가 자연스럽게 이어져야 한다.
- 폼은 긴 단일 페이지보다 단계별/섹션별 입력이 적합하다.
- 모바일 폼의 다음/완료 액션은 화면 하단 안전 영역을 고려해 고정하고, 마지막 입력값을 가리지 않도록 폼 하단 여백을 둔다.
- 체크리스트 상태 변경은 한 손 조작이 가능해야 한다.
- 트립 상세에서는 카테고리별 진행률을 기본 노출하고 필요한 묶음과 메모 편집만 펼쳐 긴 모바일 스크롤을 줄인다.
- 체크 상태와 메모 저장은 페이지 전환 없이 백그라운드에서 처리하고, 열린 카테고리·메모 UI를 유지한 채 Sonner로 결과만 알린다.
- 트립 공유는 링크 권한과 계정 사용자 초대를 하나의 공유 패널에서 관리한다.
- 수정·공유·복제·삭제 같은 관리 기능은 `트립 관리` 메뉴와 하단 시트형 다이얼로그로 제공한다.
- 완료된 사용자 액션은 Sonner 토스트로 확인시킨다.

### 데스크톱

- 모바일 1열 구조를 기반으로 2열 레이아웃으로 확장한다.
- 앱 전체 내비게이션은 상단 헤더 하나로 유지한다. 트립 상세 내부에서는 현재 트립의 개요·체크리스트·비용을 나누는 로컬 사이드바를 사용할 수 있다.
- 추천 결과 화면에서는 추천 카드와 비용/필요 항목 요약을 나란히 보여줄 수 있다.
- 트립 상세 화면은 개요, 준비 체크리스트, 비용·정산 작업공간으로 분리하고 한 번에 한 기능에 집중하게 한다.
- 모바일에서는 로컬 사이드바 대신 상단 탭으로 전환한다.

## 컴포넌트 원칙

- 버튼, 카드, 탭, 다이얼로그, 토스트, 폼 필드는 shadcn/ui 스타일을 우선 사용한다.
- Select와 Date Picker는 native control이 아니라 shadcn/Radix 기반 컴포넌트를 사용한다.
- 아이콘은 lucide-react를 사용한다.
- 조건 입력 폼은 react-hook-form + zod로 검증한다.
- 숫자 입력, 선택 옵션, 우선순위 선택은 모바일에서 터치하기 쉬운 컨트롤을 사용한다.
- 외부 링크 버튼에는 외부 링크 아이콘을 함께 표시한다.
- 연속된 주요·보조 CTA는 링크 요소의 표시 방식과 무관하게 일관된 세로 간격을 유지한다.

## 디자인 시스템 문서

세부 디자인 토큰, 컴포넌트 원칙, 페이지별 가이드는 `docs/design.md`를 기준으로 한다.

## 지도 정책

- 스키장 비교 화면은 Kakao Maps JavaScript API를 지연 로드한다.
- `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`가 없거나 지도 로드에 실패해도 검색·후보 목록·외부 지도 링크는 동작해야 한다.
- 위치가 검증되지 않은 장소를 임의 좌표로 지도에 표시하지 않는다.
- Kakao Place ID와 검증 좌표가 있는 장소를 우선 표시하고 렌탈·숙박 마커는 색상 외 문자 표식도 함께 사용한다.
- 네이버 지도와 카카오맵 외부 링크는 정확한 위치 확인용 보조 경로로 유지한다.

## 시각화 정책

MVP에서는 복잡한 차트를 만들지 않는다.

표시할 요약:

- 총 예상 비용.
- 비용 항목별 금액.
- 준비 진행률.
- 예약/확인 필요 항목 수.

## 접근성/사용성

- 주요 CTA는 모바일에서 엄지 영역에 배치한다.
- 가격, 날짜, 상태값은 텍스트만이 아니라 시각적 구분을 함께 제공한다.
- 색상만으로 상태를 구분하지 않는다.
- 외부 링크 이동은 사용자가 명확히 인지할 수 있어야 한다.
