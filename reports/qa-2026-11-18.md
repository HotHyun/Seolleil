# 설레일 완성도 평가 · QA · UX 제안 (2026-11-18)

## 1. 완성도 평가

**종합: MVP 범위 기준 완성도 높음 (약 85%).** 정적 시즌 데이터·추천·비용·트립 공유·인증이 모두 구현되어 있고 운영 중이다. 남은 문제는 기능 부재보다 테스트/CI 위생, 린트 부채, 데이터-테스트 불일치, 몇 가지 UX 마찰이다.

| 영역 | 평가 | 근거 |
|---|---|---|
| 기능 범위 | 상 | `docs/product/mvp.md`의 포함 항목(추천, 비용, 트립, 체크리스트, 공유 링크, 계정 초대, 내 트립) 라우트·코드 존재 |
| 데이터 품질 | 상 | `data:validate` 통과(경고 406건), 출처·확인일·신뢰도 모델 유지 |
| 타입 안정성 | 상 | `tsc --noEmit` 오류 0 |
| 테스트 | 중 | 단위 88/91 통과, 3개 스위트 로드 실패(아래 B1, B2) |
| 린트 | 하 | eslint 20 errors / 18 warnings |
| 성능(체감) | 중 | 공개 라우트 TTFB 0.5~2.7s (curl, 첫 요청 기준) |
| 접근성 | 중 | 이미지 alt 없는 `<img>` 35개(/resorts), 터치 타깃 36px 미만 요소 다수 |
| 운영 | 상 | `/api/health` 200, 404/307 정상 처리 |

## 2. QA 결과 (실행한 것 / 못 한 것)

실행: `tsc`, `vitest`, `data:validate`, `eslint`, 운영 공개 라우트 12개 상태 확인, 375px 모바일에서 `/`, `/plan`, `/recommendations`, `/resorts`, `/login` 확인(읽기 전용).

**실행하지 않음(승인 필요/환경 제약):** 트립 생성·수정·공유·초대 등 쓰기 흐름(`test:e2e:production`은 운영 Firestore에 쓰므로 요청 시에만), 로컬 Playwright(빌드+서비스키 필요), 이메일/OAuth 왕복, 데스크톱 레이아웃 전수 검사, `data:links`(외부 링크 점검).

라우트 상태: `/ /plan /recommendations /resorts /resorts/high1 /login /invite/accept /admin/data-quality /api/health` = 200, `/my-trips` = 307(비로그인 리다이렉트), 잘못된 `/share/*`, `/trips/*`, 임의 경로 = 404.

## 3. 고쳐야 할 항목 (우선순위순)

### 버그 / 회귀
- **B1 (높음) `server-only` 미선언** — `src/lib/{firebase,session,token-vault,firebase-auth-token}.ts`가 `server-only`를 import하지만 `package.json`에 의존성이 없다. Next 번들에서는 동작하지만 Vitest에서는 `Cannot find package 'server-only'`로 `session`, `trip-identity`, `trip-security` 3개 스위트가 로드 실패한다. CI(`pnpm install --frozen-lockfile` 후 `pnpm test`)도 동일하게 실패할 가능성이 높다. 수정: `server-only`를 devDependency/dependency로 추가하거나 `vitest.config.ts`에 빈 모듈 alias. 보안 관련 테스트(`trip-security`)가 현재 실행되지 않는 점이 가장 큰 위험이다.
- **B2 (중) 정적 데이터 테스트 3건 실패** — `tests/unit/static-data.test.ts`: High1 인근 숙소 기대 5 vs 실제 8, 26/27 전환 레코드 필드 불일치, Phoenix 26/27 `preliminary` 기대 불일치. 데이터가 최신 가격 검토 커밋(`e9e776a`)로 갱신되었으나 테스트가 따라가지 않은 것으로 보인다. 데이터 쪽이 맞는지 확인 후 테스트 기대값을 갱신.
- **B3 (중) 린트 errors 20건** — 대부분 `react-hooks/set-state-in-effect`(localStorage/마운트 동기화: `trip-workspace-nav`, `theme-toggle`, `trip-builder-form`, `task-list`, `progress`, `status-select`, auth 컴포넌트 등), `@next/next/no-html-link-for-pages`(layout, auth-nav), 생성 스크립트 `require()` 2건(`scripts/playwright/generated/*`는 lint 제외 권장). CI가 lint를 돌리지 않아 누적된 상태. 하이드레이션 시 깜빡임 가능성도 있어 `useSyncExternalStore`/lazy initializer로 정리 권장.
- **B4 (낮음) 미사용 의존성** — `gsap`이 `package.json`에 있으나 `src`에서 사용되지 않는다. 제거 시 번들/설치 크기 감소.
- **B5 (낮음) 도구 환경** — `pnpm`이 샌드박스에서 글로벌 lockfile 쓰기로 실패, `tsx` CLI는 `/tmp` IPC 소켓이 필요. 제품 버그가 아니라 이번 QA 환경 제약(`node --import tsx`로 우회).

### 확인 필요 (미검증)
- **V1** 홈 히어로가 내장 브라우저(패널 숨김 상태)에서 `hero-reveal`(opacity 0 + blur 8px, `animation-fill-mode: both`) 시작 상태로 멈춰 보였다. 숨김 탭의 애니메이션 스로틀로 추정되며 실제 사용자 영향은 미확인. 다만 JS/애니메이션 지연 시 히어로 텍스트가 비어 보이는 구조이므로 LCP 텍스트는 애니메이션 없이 보이게 하는 편이 안전.
- **V2** `/plan` 모바일 첫 화면 상단에 값이 비어 있는 아이콘 칩 2개(날짜 칩/지역 칩 형태)가 보인다. 요약 칩이 값 입력 전 빈 상태로 렌더되는지 확인 필요.

## 4. UX 개선 제안

1. **플랜 요약 칩 빈 상태** — V2의 칩은 값이 없으면 숨기거나 "날짜 선택", "지역 선택" 플레이스홀더를 보여 준다.
2. **플랜 CTA 하단 고정 바** — 모바일에서 하단 고정 "다음 단계" 버튼이 입력 필드를 가린다. 스크롤 영역 하단 패딩을 충분히 확보하고, 필수값(날짜) 미입력 시 버튼 옆에 이유를 표시한다.
3. **날짜 없이 추천 진입 허용 시 명시** — `/recommendations`는 쿼리 없이도 기본 조건으로 결과를 보여 준다. 상단에 "기본 조건(서울 강남·2명)으로 계산됨"을 눈에 띄게 하고 `조건 다시 입력`을 상단 고정에 가깝게 배치.
4. **추천 비교표 가로 스크롤** — "표를 좌우로 밀어 3곳을 비교"는 모바일에서 발견성이 낮다. 3곳을 카드 3장 세로 비교(또는 첫 열 sticky + 스크롤 그림자)로.
5. **영어 섹션 라벨 혼용** — `Recommendations`, `SKI MAP` 같은 영문 키커가 한국어 UI와 섞인다. 한국어로 통일.
6. **스키장 목록 지도 우선 레이아웃** — `/resorts`는 첫 화면이 지도+선택 카드가 대부분을 차지하고 제목·목록은 스크롤해야 보인다. 모바일에서는 목록(필터 칩)을 먼저, 지도는 보조(접힘/탭 전환)로. 지도 카드가 마커를 가리는 점도 개선.
7. **접근성** — 이미지 alt 누락(35개) 보강, 헤더 링크·칩의 터치 영역 44px 확보, 지도 대체 텍스트/목록 제공.
8. **가격 신뢰도 노출** — 추천 표의 "가격 신뢰도: 확인필요"를 색/아이콘+툴팁으로 설명하고, 지난 시즌(25/26) 참고 가격 배너를 접을 수 있게(첫 방문 이후 재노출 최소화).
9. **로그인 페이지 맥락** — "내 트립 저장하기" 화면에서 비로그인으로도 계속 사용할 수 있다는 점("로그인 없이 계속")을 보조 링크로 추가. 가입/로그인 모드 전환이 텍스트 링크 한 줄이라 모드 구분(탭)을 명확히.
10. **로딩 체감** — 공개 라우트 첫 요청 2초대. `/plan`·`/recommendations`가 정적 렌더 가능한지 확인하고 캐시 헤더/ISR 점검, 추천 계산 중 스켈레톤 제공.

## 5. 권장 후속 순서

1. B1(`server-only`) + B2(테스트 기대값) → `pnpm test` 전부 통과시키고 CI 재확인.
2. 린트 errors 정리 후 CI에 `lint` 추가.
3. UX 1·2·4·5(저비용 항목) 일괄 반영.
4. 사용자 승인 하에 로컬/운영 E2E로 쓰기 흐름(트립 생성→체크리스트→공유 링크→폐기) 회귀 확인.
